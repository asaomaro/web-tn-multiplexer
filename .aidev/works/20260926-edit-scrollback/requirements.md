# 要件: pane のスクロールバックを `$EDITOR` で開く（herdr の `edit_scrollback`）

## 背景 / 課題

- herdr には、フォーカス中の pane が保持しているスクロールバック（画面を含む）を一時ファイルに書き出し、
  `$EDITOR` で開いた一時的な拡大表示の pane を出す操作 `edit_scrollback`（既定 `prefix+e`）がある
  （一次資料の確認結果は下記「herdr の挙動（一次資料）」）。長い出力を検索・抜き出し・保存するのに、
  使い慣れたエディタの検索・範囲選択・ヤンク・保存をそのまま使える。
- 本製品では `prefix+e` が「未対応（後続: 端末機能の拡張）」のトーストを出すだけ
  （`packages/web/src/keys/keymap.ts:25-29` の `NOT_YET_BINDINGS`）。`docs/herdr-parity.md` の H11 も
  「新規後続(提案)」のまま。backlog（`.aidev/backlog/product-roadmap.md:244`）の「端末機能の拡張」の片方。
- ブラウザの xterm.js で遡れる行数は設定次第で、copy モードでの検索・選択は herdr の copy モード相当に
  留まる。エディタで開けば、ブラウザ・端末の制約に縛られずに全文を扱える。

## 目的 / ゴール

- 利用者が、ブラウザから 1 操作で、pane のスクロールバック全体をサーバ側の `$EDITOR` で開いた状態に
  なれる。エディタを終えれば、開く前の pane・拡大表示の状態へ戻っている。
- 書き出したスクロールバックが、他のユーザーに読まれる場所・権限で残らず、エディタを閉じた後に
  サーバ上へ残らない状態。
- `prefix+e` が「未対応」の案内ではなく実際の操作になり、キー一覧・キー設定画面で他の操作と同じく
  割り当てを変えられる状態。herdr との対応表（`docs/herdr-parity.md` H11）が実態に合っている状態。

（`.aidev/charter.md` はこの PJ に無いので、charter ゴールへの紐づけは省く。）

## ユーザーストーリー

- US1: ブラウザで作業する開発者として、長いビルドログやエージェントの出力を、使い慣れたエディタで
  検索・抜き出し・保存したい。なぜなら xterm.js のスクロールと copy モードだけでは、長い出力を
  扱うのが遅く、エディタの検索・置換・保存がそのまま使える方が速いから。（受け入れ: AC1, AC2, AC3, AC4, AC5）
- US2: 共有サーバでこのツールを動かす運用者として、書き出したスクロールバック（秘密が混ざりうる）が
  他のユーザーに読まれず、使い終わったら消えていてほしい。なぜならスクロールバックにはトークンや
  パスワードが写り込むことがあり、一時ファイルがそれを漏らす経路になってはならないから。（受け入れ: AC6, AC7, AC8, AC12, AC14）
- US3: キー割り当てを自分用に変えている利用者として、この操作も他の操作と同じ画面で割り当て・確認したい。
  なぜなら操作ごとに設定の場所が違うと覚えられないから。（受け入れ: AC9, AC10, AC13）
- US4: herdr から移ってきた利用者として、`prefix+e` が herdr と同じ意味で動いてほしい。なぜなら指が
  覚えている操作をそのまま使いたいから。（受け入れ: AC1, AC9, AC11）

## スコープ

### 対象

- フォーカス中の pane のスクロールバック（サーバのミラーが保持している全行＋画面）を、平文で一時ファイルに
  書き出し、サーバ上で `$EDITOR` を起動した新しい pane を、元の pane の tab に拡大表示で開く操作。
- エディタが終わった（または pane が閉じられた）ときの後片付け（一時ファイルの削除）と、焦点・拡大表示の
  状態の復帰。サーバを止めたときの後片付け。
- ブラウザからこの操作を要求するためのサーバ↔ブラウザの要求（protocol）の追加。
- キー割り当てのカタログへの登録（既定 `prefix+e`）と、`prefix+e` の「後続」案内の撤去。キー一覧・キー設定
  画面への反映。
- `docs/herdr-parity.md` の H11 行と利用者向け docs（`docs/verification.md` のキーの説明と手動確認の項目）の更新。
- backlog 行の分割（この分を `[x]`、端末内の画像表示〔H13〕を `[ ]` の兄弟行として残す）。

### 対象外

- 端末内の画像表示（Kitty graphics。H13）——backlog に残す。
- 編集結果を元の pane へ書き戻す・貼り付ける機能（herdr にも無い。エディタでの保存は一時ファイルに対する
  もので、閉じれば消える。残したければエディタで別名保存する）。
- 色・装飾（ANSI の制御列）を保ったままの書き出し（herdr も平文）。
- エディタをブラウザ側（利用者の手元の機器）で開くこと。エディタが動くのはサーバ上の pane の中。
- サーバ再起動をまたいだエディタ pane の扱いの herdr 合わせ（herdr は一時 pane を保存から外す。
  本製品の保存形式に「一時 pane」を足すのは影響が広いので、この work では扱わない。再起動後の振る舞いは
  F10 のとおりとし、herdr との差を `docs/herdr-parity.md` に書く）。
- 外部操作の API・CLI（`wtmctl`）からの呼び出し口の整備（別 work〔エージェント自動化 API / CLI〕が並行して
  進めている。protocol のメソッドとしては使えるが、CLI のサブコマンドは足さない）。
- herdr の成功時のトースト（新しい pane が拡大表示で開くこと自体が結果として見えるため出さない）。

## 機能要件

- F1: 操作の対象は、その操作を行ったブラウザでフォーカス中の pane。
- F2: 書き出す内容は、サーバのミラーがその時点で保持している全行（スクロールバック＋画面）を、
  折り返しで分かれた行を 1 行に戻した平文（制御列なし）とする。末尾の空行（画面の使っていない下側）は含めない。
- F3: 一時ファイルは、サーバを動かしているユーザー以外が読めない権限・場所に作る。既存のファイルや
  シンボリックリンクを上書き・追従しない（新規作成に限る）。名前は推測できないものにする。置き場所は OS の
  一時ディレクトリの下に作る**この操作専用の一時ディレクトリ**（Unix で所有者のみ。Windows は利用者ごとの一時ディレクトリの既定の権限に従う）で、OS の一時ディレクトリ（`TMPDIR` 等、サーバの環境で決まる。利用者名などに由来して空白や記号を含みうる）の下とする。
- F4: エディタのコマンドは、サーバのプロセスの環境変数 `EDITOR`（未設定・空なら `vi`）とし、herdr と同じく
  引数付きの値（例 `code -w`・`nvim -R`）を許す。一時ファイルのパスは、シェルのコマンド文字列に埋め込まず、
  パスに何が含まれてもシェルの構文として解釈されない渡し方をする。Windows のサーバでは herdr と同じく
  `VISUAL`→`EDITOR` を使い、どちらも無ければ失敗にする（herdr は GUI の `notepad.exe` だが、本製品はブラウザが
  別の機器にありうるので、サーバの画面に GUI が開いても利用者には見えない）。
- F5: エディタは、対象の pane と同じ tab に新しい pane として開き、その pane を拡大表示にして焦点を移す。
  作業場所は対象の pane の場所。
- F6: エディタが終わる（pane のプロセスが終わる）か、利用者がその pane を閉じると、一時ファイル（と、それを
  入れた一時ディレクトリ）を消す。サーバを止めたときに残っていた一時ファイルも消す。
- F7: エディタの pane が閉じたとき、対象だった pane がまだあれば、焦点をそこへ戻し、拡大表示の状態を
  開く前（対象の pane が拡大表示だったならその状態、そうでなければ解除）に戻す。
- F8: 失敗（対象の pane が無い・端末が無い・一時ファイルを作れない・エディタを起動できない）したら、
  一時ファイルを残さず、ブラウザに失敗のトーストを出す。新しい pane は残さない。
- F9: 操作をキー割り当てのカタログに `edit_scrollback`（pane 群。既定 `prefix+e`）として登録し、キー一覧・
  キー設定画面に出す。`prefix+e` の「後続」の案内は外す。
- F10: サーバを再起動したとき、エディタの pane はエディタとしては戻らない（一時ファイルは F6 で消えているため）。
  pane の保存・復元の既存の規則に従い、同じ場所の普通のシェルの pane として戻る（herdr は保存から外す。差として docs に書く）。

## 非機能要件 / 制約

- 安全: 一時ファイルのパスはサーバが決め、ブラウザから受け取らない。ブラウザから受け取るのは pane の id
  だけ（既存の要求と同じ検証を通す）。エディタのコマンドはサーバの環境変数から取り、ブラウザから受け取らない。
- 互換: 既存の protocol の要求・イベントの形を変えない（要求を 1 つ足すだけ）。既存のキー割り当て
  （利用者の上書き）を壊さない——`prefix+e` を別の操作に割り当てている利用者はそのまま。
- 並行作業: 外部操作 API / CLI の work と同じ `packages/protocol/src/messages.ts`・`packages/server` を触るので、
  差分は追加に留め、既存行の書き換えを最小にする（マージの衝突を小さくする）。
- 検証は vitest・`pnpm -s typecheck`・`pnpm -s build`・`aidev smoke`。E2E（playwright）は走らせない（利用者の方針）。
- プロジェクト規約: 足した挙動には回帰テストを書き、足した箇所を 1 つずつ壊してテストが落ちることを確かめる
  （`.aidev/conventions/regression-negative-control.md`）。
