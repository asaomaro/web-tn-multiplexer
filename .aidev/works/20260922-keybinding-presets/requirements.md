# 要件: キーバインドのプリセット

紐づく charter ゴール: `.aidev/charter.md` は本リポジトリに無いため対象外。

## 背景 / 課題

20260921-keybinding-customization で、prefix と 34 個の操作の割り当てを設定画面の節「キー」で
自由に変更・保存できるようになった。その work では「herdr が文書で勧める `ctrl+alt` の直接のキー一式」を
1 つのボタン（［herdr のおすすめの直接のキー（ctrl+alt）を足す］）で足せる仕組み（`applyRecommended`）も
実装したが、そのボタンが指す一式は `RECOMMENDED_DIRECT` の 1 つに固定されていた。

backlog（`.aidev/backlog/product-roadmap.md` 19 行目）は、herdr 互換以外のプリセット（tmux 風など）も
選べるようにすることを次の課題として残しており、「プリセットは `keys/bindings.ts` の `ActionDef.defaults`
と同じ形の表で持てる」という設計の方向性まで示している。

## 目的 / ゴール

利用者が、慣れ親しんだ別のツール（tmux 等）のキー操作に近い割り当てを、herdr 互換の一式と同じように
1 回の操作でまとめて追加できる状態。追加できるプリセットが 1 種類に固定されておらず、複数から選べる状態。

## ユーザーストーリー

- US1: tmux を使い慣れた利用者として、tmux 風のキー操作をこの製品でも足したい。なぜなら、複数のツールで
  指の記憶（左右分割は `%`、pane 移動は矢印キー、など）を使い分ける負担を減らしたいから。
  （受け入れ: AC1, AC2, AC3, AC4, AC7, AC-I1〜AC-I5）
- US2: このコードに今後も機能を足す開発者として、新しいプリセットを `ActionDef.defaults` と同じ形の表を
  1 つ足すだけで追加できる状態にしたい。なぜなら、次にプリセットが増えたときの実装コストと
  レビューの負担を抑えたいから。（受け入れ: AC5, AC6）

## スコープ

### 対象

- 既存の単一目的のボタン（［herdr のおすすめの直接のキー（ctrl+alt）を足す］）を、複数のプリセットから
  選んで足せる UI（`<select>` 等 + ［足す］ボタン）に一般化する。
- 新しいプリセット「tmux 風」を追加する（tmux の DEFAULT KEY BINDINGS に倣う。対応表は design で確定）。
- プリセットの表の形を一般化する：`RECOMMENDED_DIRECT`（`[ActionId, chord][]`、chord は常に直接のキー）を、
  `ActionDef.defaults` と同じ書式（`prefix+` 付きも可）の表を受けられるよう `applyRecommended` を拡張する。
- 足す操作は既存どおり「追加」（すでにある割り当てを壊さない・置き換えない）。

### 対象外

- 節「キー」の操作の絞り込み UI・衝突したときの「こちらへ移す」導線・macOS の非 US 配列での Option
  chord 表示の修正・Keyboard Lock API（全画面時だけキーを渡す）——いずれも
  `.aidev/backlog/product-roadmap.md` 31 行目「キーの設定の使い勝手」に別途残っており、この work では扱わない。
- プリセットの「置き換え」semantics（今の割り当てを一旦リセットしてプリセットで上書きする動作）は行わない。
  既存の「追加」方式（`applyRecommended` の冪等・非破壊の挙動）を踏襲する。
- tmux 風プリセットで、この製品に 1:1 で対応する操作が無いもの（`swap_pane_*` の方向つき入れ替え、
  resize の連続操作等）への対応表作りはしない（該当操作はプリセットの表に含めない）。
- サーバー・protocol の変更は無い（ブラウザの `wtm.prefs.v1` のみ）。

## 機能要件

- プリセットは複数から選べる（最低 2 つ：herdr のおすすめ〔ctrl+alt〕・tmux 風）。
- 選んだプリセットを「足す」と、その表にある各操作へ、まだ持っていない chord を追加する
  （既存の `applyRecommended` の add / already / skipped の挙動を維持）。
- tmux 風プリセットの内容は tmux 公式マニュアル（`tmux.1` の DEFAULT KEY BINDINGS）の既定に倣う。
  1:1 で対応しない操作は表に含めない（上の「対象外」）。
- 結果は既存と同じ `role="status"` の案内文に出す。

## 非機能要件 / 制約

- 既存の `RECOMMENDED_DIRECT`（herdr のおすすめ一式）の内容・単体テストで固定している一覧は変えない
  （AC6）。
- 新しいプリセットの追加が、`[ActionId, binding][]` の表を 1 つ増やすだけで済む設計にする
  （開発者向けの非機能要件。AC5）。
- 既存の「すべて既定に戻す」で、プリセットで足した分も含めて全部消える（新規の巻き戻し経路は作らない。AC7）。

## 完了条件 (受け入れ基準)

- [ ] AC1: 設定画面の節「キー」に、プリセットを選ぶ UI（`<select>` 等）と［足す］ボタンがあり、
      「herdr のおすすめ（ctrl+alt）」と「tmux 風」の少なくとも 2 つから選べる。
- [ ] AC2: 「tmux 風」を選んで［足す］を押すと、tmux の既定に倣う chord がそれぞれの対応する操作へ
      追加される（まだ持っていない場合のみ）。既存の割り当ては残る。
- [ ] AC3: 同じプリセットを二度足しても壊れない（冪等）。既にそのチップを持つ操作はスキップとして
      案内文に出る（「すでにあった分」。既存パターンを踏襲）。
- [ ] AC4: 別の操作・prefix と衝突する chord は足さず、理由つきで案内文に出る
      （既存の `applyRecommended` の判定をそのまま再利用する）。
- [ ] AC5: 新しいプリセットを追加するときの変更点が、`[ActionId, binding][]` の表を 1 つ増やすだけで
      済む（コードコメントか `decisions.md` で、その設計意図を示す）。
- [ ] AC6: 既存の「herdr のおすすめの直接のキー（ctrl+alt）を足す」の動作（対象の一覧・結果の文言・
      冪等性）が、プリセット化後も変わらない（回帰なし。既存テストで担保）。
- [ ] AC7: 「すべて既定に戻す」で、プリセットで足した分も含めて全部既定へ戻る（既存の挙動のまま。
      変更が不要なことをテストで確認する）。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: プリセットの選択欄はダイアログ内の通常の項目で、独立した開閉は持たない。
      `<select>` 自体の開閉はブラウザ既定に任せる。ダイアログを閉じても選択（まだ足していない値）は
      保持してよい（確定操作ではないので、取り消すべき状態が無い）。
- [ ] AC-I2 確定 / 取り消し: ［足す］ボタンを押した時点で確定・即時反映（既存の「おすすめ」ボタンと
      同じ。確認ダイアログは挟まない）。押す前の選択は何も変えない。反映を取り消したいときは、
      既存の［削除］／［既定に戻す］／［すべて既定に戻す］で行う（新規の取り消し導線は作らない）。
- [ ] AC-I3 キーボードだけで完結するか: Tab で `<select>` へ移動 → 矢印キーで選ぶ → Tab で
      ［足す］へ移動 → Enter で確定、の流れがマウス無しで通る。
- [ ] AC-I4 フォーカスの行き先: ［足す］を押した後もフォーカスは［足す］ボタンに残る
      （既存の「おすすめ」ボタンと同じ。押した場所を離れない）。
- [ ] AC-I5 既存の操作を妨げないか: `<select>` の開閉・矢印キー操作は、ダイアログの他のキー処理
      （Esc で閉じる等）やキーの取り込み待ち（`.keys-capture`）を妨げない
      （両者は独立した状態で、同時に取り込み待ちにはならない）。
