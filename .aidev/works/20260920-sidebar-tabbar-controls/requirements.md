# 要件: サイドバーとタブバーに、マウスで使える操作を足す

## 背景 / 課題

利用者から、herdr にあってこの製品に無い操作が 4 件挙がった。いずれも**キー操作は既にあるが、
マウスで触れる導線が無い**（または機能ごと無い）もの。現状はリポジトリのコードで裏が取れている。

1. **サイドバーを折りたたむボタンが無い。** 折りたたみの状態（`store/view.ts` の `sidebarCollapsed`）は
   あり、`Sidebar.vue` はそれを読んで幅を `3em` にする（`Sidebar.vue` の `.sidebar-collapsed`）。
   しかし切り替える手段は `prefix+b`（`keys/keymap.ts` の `toggleSidebar`）だけで、
   **`Sidebar.vue` に `<button>` は 1 つも無い**。
2. **workspace の一覧の下に「新規」「メニュー」に当たるボタンが無い。** 新しい workspace を作る手段は
   `prefix+shift+n`（`keymap.ts` の `newWorkspace`）だけで、UI からの導線が無い。
   全体に効く操作（ヘルプ・移動・切り離し）もキーだけで、まとめて開く入口が無い。
3. **タブバーに「＋」が無い。** 新しいタブを作る導線は `prefix+c` と、
   **タブを右クリックしたときのメニューの「新規」**（`ContextMenu.vue`）だけ。
   後者はタブが 1 つも無い workspace では右クリックの対象が消えるので、導線ごと無くなる。
4. **agents の一覧に並び順の切り替えが無い。** 並びは `session.panes`（`store/session.ts` の `Map`）の
   **挿入順そのまま**で、ソートもグルーピングもしていない（`Sidebar.vue` の `agents` computed）。
   見出しも無いので、切り替えるボタンを置く場所も無い。

`docs/herdr-parity.md:38`（H19「サイドバー（Space パネル・Agent パネル）・**折りたたみ・ソート**」）は
MVP の範囲を「既定の表示だけ」としていた。そこで見送った部分が、実際に使うと足りなかった。

### herdr（`da6bcd5`）ではどうなっているか

この work の参照元。**同じにするのではなく、Web に読み替える**（その判断は design で行う）。

- **折りたたみ**: サイドバーの**右下 1 セル**に `«`（展開時）/ `»`（折りたたみ時）。
  クリックで反転し、状態を保存する（`src/client/shell/sidebar.rs`・`mouse.rs`）。キーは `prefix+b`。
- **new / menu**: workspace 区画の**最下段**に、左へ `" new"`・右へ `"menu"`（`src/client/shell/sidebar.rs`）。
  `new` は押すと即 workspace を作る（既定では名前を尋ねない）。`menu` は上方向へ開くメニューで、
  項目は `settings` / `keybinds` / `reload config` /（更新があれば）`what's new` / `detach`
  （`src/client/shell/global_menu.rs`）。**どちらもマウス専用**（キーからは開けない）。
- **タブの ＋**: タブ列の右に `" + "`（幅 3。`src/client/shell/tabs.rs`）。押すと新規タブ。
  既定では名前入力が開き、**初期値は「そのワークスペースの現タブ数 + 1」**。
- **agents のソート**: `agents` の見出しの右端に、**ソート名そのものがボタン**として出る
  （`grouped` / `priority`。`src/client/shell/agent_sidebar.rs`）。
  `priority` は「状態の優先度の降順 → 状態が最近変わった順」、`grouped` は**ソートせず**
  workspace 順 → tab 順 → pane 順。クリック専用で、選んだ順序は保存される。

## 目的 / ゴール

- サイドバーの開け閉めが、**キーを知らなくてもできる**状態。
- 新しい workspace を作る導線と、全体に効く操作の入口が、**画面の上に見えている**状態。
- 新しいタブを作る導線が、**タブが 1 つも無いときでも消えない**状態。
- エージェントの一覧を、**「手を動かす必要がある順」でも「workspace ごと」でも見られる**状態。
  どちらで見ているかが画面から分かり、選んだ並びが次に開いたときも残っている。

## ユーザーストーリー

- US1: **マウスで操作する人**として、サイドバーをボタンで畳みたい。
  なぜなら、`prefix+b` を知らないと畳めず、ヘルプを開くまで存在に気づけないから。（受け入れ: AC1, AC2, AC12）
- US2: **マウスで操作する人**として、新しい workspace をボタンで作りたい。
  なぜなら、いまは `prefix+shift+n` しか手が無く、画面のどこにも「作る」導線が無いから。（受け入れ: AC3）
- US3: **マウスで操作する人**として、全体に効く操作をひとつの入口から使いたい。
  なぜなら、ヘルプ・移動・切り離しがそれぞれ別のキーに散っていて、画面からは辿れないから。（受け入れ: AC4, AC5）
- US4: **タブを使う人**として、タブバーの ＋ で新しいタブを作りたい。
  なぜなら、いまの導線（タブの右クリック）は**タブが無いと消える**ので、タブを全部閉じると
  キーを使うしかなくなるから。（受け入れ: AC6）
- US5: **複数のエージェントを見ている人**として、手を動かす必要がある順に並べ替えたい。
  なぜなら、pane が増えるほど「止まっているのはどれか」を挿入順の一覧から探すのが難しくなるから。（受け入れ: AC7, AC8, AC9）
- US6: **毎日使う人**として、選んだ並び順が次に開いたときも残っていてほしい。
  なぜなら、開くたびに選び直すなら切り替えの価値が半減するから。（受け入れ: AC10）
- US7: **画面の狭い人**として、折りたたんだときもボタンが邪魔にならないでほしい。
  なぜなら、折りたたみの幅（`3em`）にラベルまで出ると、畳んだ意味が無くなるから。（受け入れ: AC11）

## 機能要件

- サイドバーに折りたたみ/展開のボタンを置く。**折りたたんだ状態でも押せる**（戻せないと行き止まりになる）。
- spaces 区画の下に「新しい workspace を作る」ボタンと「全体のメニューを開く」ボタンを置く。
- 全体のメニューの項目は、**いま存在する全体操作**（ヘルプ＝キー割り当て・移動・切り離し）に限る。
- タブバーの右端に「新しいタブ」のボタンを置く。**タブが 0 個でも押せる**。
- agents 区画に見出しを置き、その右端に**現在の並び順の名前がそのままボタン**になっているものを置く
  （herdr と同じ流儀。押すたびに 2 つの順序を行き来する）。
- 並び順は 2 つ:
  - **grouped**（既定）: いまの並び（workspace 順 → tab 順 → pane 順）を変えない。
  - **priority**: 状態の優先度（`store/seen.ts` の `STATE_PRIORITY`。blocked 4 > done 3 > working 2 > idle 1 > unknown 0）の
    降順。同点は**状態が最近変わった順**（`AgentInfo.since`。epoch ms）。
- 選んだ並び順を保存し、次に開いたときに復元する。
- 折りたたみ時は、ボタンの**ラベルを出さず**、幅 `3em` に収まる形にする。

## 非機能要件 / 制約

- **既存のキー操作を変えない**（`prefix+b` / `prefix+shift+n` / `prefix+c`）。ボタンは同じ動作への別の入口。
- **既存のクラス名を消さない**。E2E と単体テストが掴んでいる（`.sidebar` / `.sidebar-row` /
  `.sidebar-spaces` / `.sidebar-agents` / `.sidebar-collapsed` / `.tab-bar-item` / `.tab-bar-item-active`）。
  消すならテスト側も同じ変更に含める。
- **足すボタンを、件数を数えている既存のセレクタに一致させない**。
  `workspace-tab-pane.spec.ts` は `.sidebar-spaces .sidebar-row` と `.tab-bar-item` の**件数**を
  `toHaveCount` で確かめている（workspace が 2 つ・タブが n 個、など）。ボタンにこれらのクラスを
  付けると件数がずれて既存テストが壊れる。**別のクラス名にする**。
- **ボタンを足してもサイドバー・タブバーの幅と高さの扱いを壊さない**。どちらも pane に使える大きさを
  決めているので、高さが増えると PTY の行・列が変わる（`terminal-app.spec.ts` が折りたたみで
  列が増えることを確かめている）。
- 配色は既存の CSS 変数（`App.vue` の `--wtm-*`）に従い、色を直接書かない。
- **ボタンはキーボードでも使えること**（Tab で到達でき、Enter / Space で押せる）。
  ただし端末のキー入力を奪わないこと（`main.ts` の window の keydown へ二重に流さない）。

- [ ] AC3: spaces 区画の下に「新規」のボタンがあり、押すと `workspace.create` が送られる
      （`prefix+shift+n` と同じ結果になる）。
- [ ] AC4: spaces 区画の下に「メニュー」のボタンがあり、押すと全体のメニューが開く。
      項目は「キー割り当て」「移動」「切り離し」の 3 つで、それぞれ既存の `help` / `goto` / `detach` を実行する。
- [ ] AC5: そのメニューは既存の右クリックメニューと同じ操作で動く（↑↓ で移動、Enter で実行、
      Esc で閉じて元の場所へフォーカスが戻る）。
- [ ] AC6: タブバーの右端に「新しいタブ」のボタンがあり、押すと `prefix+c` と同じ名前入力が開く。
      **その workspace のタブが 0 個でも押せる**。
- [ ] AC7: agents 区画に見出しがあり、右端に現在の並び順の名前（`grouped` / `priority`）がボタンとして出る。
      押すともう一方へ切り替わり、表示も変わる。
- [ ] AC8: `priority` のとき、agents の行が「状態の優先度の降順 → `since` の新しい順」に並ぶ。
- [ ] AC9: `grouped` のとき、並びは**この work の前と同じ**（`session.panes` の順）。
- [ ] AC10: 並び順を切り替えた後、**(a) ページを再読み込みしても、(b) そのタブを閉じて開き直しても**、
      切り替えた順序で表示される。(b) を満たすには**タブの寿命を越えて残る保存先**（`localStorage` 相当）が要る
      ——既存の表示位置は `sessionStorage`（`store/view.ts`）だが、それでは US6 の「次に開いたときも残る」を満たさない。
      判定は (a) を E2E（`page.reload()` の後も同じ並び）、(b) を単体（保存した内容を新しいストアが読む。
      既存の `store/view.test.ts` の流儀）で行う。
- [ ] AC11: 折りたたみ時、足したボタンはラベルを出さず、サイドバーの幅 `3em` の中に収まる
      （横スクロールバーが出ない）。
- [ ] AC12: 既存のキー操作（`prefix+b` / `prefix+shift+n` / `prefix+c`）の動作が変わっていない。
- [ ] AC13: （**AC13・AC14 はどの US にも紐づかない横断的な基準**。新しい価値ではなく、
      既存の振る舞いを壊していないことを求めるもの）既存の単体テストと既定の E2E が通る。テスト側を直した場合は、
      直した理由が AC1〜AC12 のどれかに紐づく。
- [ ] AC14: 足したボタンが**端末の大きさを変えていない**。判定は E2E で、
      **同じ実行の中で ＋ を隠したときと表示したときの帯の高さが一致する**ことを確かめる。
      `cols` / `rows` の固定値は使わない——xterm のフォントをこの製品では指定しておらず、
      環境によってセルの寸法が変わるので再現しない（既存の `terminal-app.spec.ts` も固定値ではなく
      同じ実行の中での相対比較で確かめている）。
      併せて `terminal-app.spec.ts` の既存の確認（折りたたむと `cols` が増え `rows` は変わらない）が通ること。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 全体のメニューは「メニュー」ボタンで開き、Esc・外側のクリック・
      項目の実行で閉じる。閉じても選択状態は残らない（次に開くと先頭から）。
- [ ] AC-I2 確定 / 取り消し: メニューの項目は Enter / クリックで確定し、Esc で取り消す。
      取り消したときは何も実行されない。「新規」ボタンは押した時点で確定（取り消しは workspace を閉じる操作）。
- [ ] AC-I3 キーボードだけで完結するか: 足した 5 つのボタン（折りたたみ・新規・メニュー・＋・ソート）が
      Tab で到達でき、Enter / Space で押せる。メニューは開いた後も ↑↓ / Enter / Esc で完結する。
- [ ] AC-I4 フォーカスの行き先: メニューを開いたらメニューへ移り、閉じたら**開いたボタンへ戻る**。
      折りたたみボタンを押した後もフォーカスがそのボタンに残る（折りたたんでも消えない位置に置く）。
- [ ] AC-I5 既存の操作を妨げないか: ボタンの上のキー・ホイールを端末へ漏らさない。
      サイドバーの幅変更のつまみ・行のクリック・右クリックメニューを妨げない。

## 未確定事項 / 確認したいこと

- 全体のメニューを既存の `ContextMenu.vue` で出すか、専用の部品を作るかは design で決める
  （`ContextMenu.vue` は `view.contextMenu` の `target` が `pane` / `tab` / `workspace` のいずれかを前提にしている）。
- ソート順の保存先（`sessionStorage` か `localStorage` か）は design で決める。
  既存の表示位置の保存は `sessionStorage`（`store/view.ts`）だが、並び順は「この端末での好み」なので
  タブを閉じても残るほうが筋かもしれない。
- 折りたたみボタンの置き場所（herdr はサイドバーの右下）と、折りたたみ時にどう見せるかは design で決める。
