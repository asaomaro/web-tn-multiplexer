# 要件: pane の枠の描画モード（常に/分割時だけ/表示しない）と隙間の入切（H23 の残り）

紐づく charter ゴール: `.aidev/charter.md` は本リポジトリに無いため対象外。

## 背景 / 課題

herdr には pane の枠について 2 つの設定がある（herdr のソース `scratchpad/herdr/` で確認）。

- `ui.pane_borders`（`"auto"` / `"always"` / `"off"`。既定 `"auto"`。`src/config/model.rs:848-863`）:
  `"auto"` は**その tab が分割されているときだけ**枠を描き、`"always"` は pane が 1 つでも枠を描き、`"off"` は描かない。
  「分割されているか」は tab のレイアウトの pane 数が 2 以上か（`src/ui/panes.rs:216` の `tab.layout.pane_count() > 1`）で、
  zoom 中でも分割された tab なら分割扱い（同 `:223`）。
- `ui.pane_gaps`（既定 `true`。`src/main.rs:302-303`）: 入なら隣り合う pane をそれぞれの枠で離して描き、切なら隣り合う pane が
  境界の線を共有する（`src/ui/panes.rs:132-139`）。枠を描かない設定（`"off"`）で隙間が入なら、pane の間に 1 セルの空白を
  空ける（同 `:119-126`）。

本製品（Web 版）は、pane の枠を**常に**描く（各 pane の周りに太さ 2/4/6px の余白を取り、選ばれている pane にはその余白の中に
強調の線を引く。`packages/web/src/components/PaneFrame.vue:310-312,332-335`）。枠を分割時だけにする設定・枠を消す設定・
隣の pane との隙間を詰める設定は無い（`docs/herdr-parity.md` の H23 行で「対象外のまま」と記録され、backlog に残っている）。
前回の work（20260922-appearance-settings-rest の decisions D11）は、この 2 つが「常に余白を取る・太さを 3 段階で選ぶ」今の設計と
素直に両立しないため、`PaneLayout.vue` への手入れが要るとして見送った。

## 目的 / ゴール

- 利用者が、pane の枠を「常に」「分割しているときだけ」「表示しない」から選べ、1 つの pane だけの tab では端末を画面の端まで
  使える状態（pane 領域の外周の枠〔`paneOuterBorders`〕を入れていないとき）。
- 利用者が、隣り合う pane の間の隙間を詰められる状態（境界の線に pane が直接接する）。
- 何も設定を変えていない利用者の見た目・端末の大きさは、今と変わらない状態。

## ユーザーストーリー

- US1: 1 つの pane で作業することが多い利用者として、分割していないときは枠を出さずに端末を広く使いたい。なぜなら
  余白の分だけ端末の行・列が減り、分割していないときの枠は区切りとしての役目が無いから。（受け入れ: AC1, AC2, AC6）
- US2: 枠の装飾を好まない利用者として、枠を常に出さないようにしたい。なぜなら端末の表示領域を最大にしたいから。
  （受け入れ: AC1, AC3, AC5）
- US3: 分割して作業する利用者として、pane の間の隙間を詰めたい。なぜなら herdr と同じく、隣の pane と 1 本の境界線で
  区切られた詰まった見た目で広く使いたいから。（受け入れ: AC4, AC5, AC6, AC9）
- US4: 既存の利用者として、アップデートしても見た目が変わらないでほしい。なぜなら設定を触っていないのに端末の
  大きさが変わると、動いているアプリの表示が崩れるから。（受け入れ: AC1, AC7）
- US5: キーボードで操作する利用者として、枠を出さない設定にしても pane のメニューに今までどおり届きたい。
  なぜなら枠はメニューへの入口でもあるから。（受け入れ: AC-I3, AC-I5）
- US6: 設定を変える利用者として、設定画面で選んだ値がその場で効き、画面を閉じても残ってほしい。なぜなら見た目を
  確かめながら選び直したいから。（受け入れ: AC-I1, AC-I2, AC-I4）
- AC8（docs の更新）はストーリーに紐づかない（スコープの「対象」の 4 つ目から来る）。

## スコープ

### 対象

- 枠の描画モード（常に/分割時だけ/表示しない）の設定と、その描き分け。
- 隙間の入切の設定と、その描き分け。
- 設定画面（`prefix+s` の「表示」節）での操作、保存、別ウィンドウでの変更への追従、設定の再読み込み（`prefix+shift+r`）への追従。
- `docs/herdr-parity.md` の H23 行と、利用者向けの確認手順（`docs/verification.md`）の更新。

### 対象外

- サイドバー行の色の条件付け・独自トークン（H21）、設定の onboarding（H25b）——同じ backlog 行の残り。backlog に残す（decisions D1）。
- 分割の境界（`Splitter.vue` の線）の見た目の変更。境界はドラッグ・矢印キーで比率を変える操作部品なので、どの設定でも
  今の線のまま残す（herdr の `"off"` は線も描かないが、Web 版では操作部品を見えなくしない）。
- herdr の「`"always"` は `pane_outer_borders` が入のときだけ単一 pane を囲む」という連動。本製品の外周の枠
  （`settings.paneOuterBorders`）は pane 領域の外側に足す別の線（`App.vue:151-157`）で、pane ごとの枠の辺を消す設定では
  ないため、連動させない。
- herdr の旧形式（`true`/`false`）の値の読み込み。本製品にはこの設定の保存値がこれまで存在しない。
- モバイルの 1 列表示（`MobileShell`）。もともと枠を描かない（`PaneLayout.vue:76-79`）。
- E2E の追加・実行（利用者の方針。検証は単体テストで行い、確かめられない見た目は未検証の穴として残す）。

## 機能要件

- 枠の描画モードは 3 値。「常に」は今と同じ。「分割時だけ」は表示中の tab が分割されている（zoom 中を含む）ときだけ枠を描く。
  「表示しない」は描かない。「枠を描かない」とは、外周側（隣に pane が無い辺）の余白・選ばれている pane の強調の線・
  エージェント名のラベル（`paneAgentNameVisible` が入のとき）を描かないこと。
- zoom 中は、表示している 1 つの pane の辺をすべて外周側として扱う（画面に隣の pane が出ないため。herdr も zoom 中の pane を
  外周の辺だけで囲む〔`src/ui/panes.rs:223`〕）。「分割時だけ」の判定は zoom 中でもレイアウト上の分割で行う。
- 隙間は入切の 2 値。入は今と同じ。切は、隣の pane と接する辺の余白を無くす。
- 枠を描かず隙間が入のときは、隣の pane と接する辺にだけ余白を残す（herdr の 1 セルの隙間に当たる）。
- 枠の太さ（`paneFrameThickness`）は、余白を取る辺の太さとして今までどおり効く。
- 設定の値はこのブラウザに保存し（`wtm.prefs.v1`）、ページを読み直しても保たれる。

### 検証の範囲

- 受け入れ基準の「描く／描かない」「余白」は、単体テストで DOM（要素の有無）・class・style（各辺の余白の値）を確かめる。
  実際の画素・端末の cols/rows の変化は E2E を回さないため確かめられず、test-result.md の「未検証の穴」に残す。

## 非機能要件 / 制約

- 既定値（保存値が無い・読めない）は「常に」・隙間「入」で、今と同じ見た目・同じ端末の大きさになること（decisions D2）。
- 余白が変わると端末の置き場の大きさが変わる。端末の cols/rows は既存の追従の仕組み（`PaneLayout.vue` の `followResize`）で
  送り直されること（仕組みを新たに作らない）。
- 設定の保存・同期は既存の外観設定の仕組み（`store/settings.ts` の `readPrefs`/`writePrefs`、`storage` イベント、
  `ActionDispatcher.reloadConfig`）に合わせる。
- 枠を描かない pane では、枠の右クリック（端末の右クリックの設定に関わらずメニューを開く経路。`PaneFrame.vue:14-16`）は
  使えなくなる——押せる余白が無いため。これは利用者が枠を消すことを選んだ結果として受け入れ、設定画面の説明に書く。
  キーボードの経路（AC-I5）は残す。

## 完了条件 (受け入れ基準)

- [ ] AC1: 設定に枠の描画モード（常に/分割時だけ/表示しない）と隙間（入/切）があり、保存値が無い・読めない値のときは
  「常に」・「入」になる。この既定では、単一 pane・分割のどちらの tab でも、各 pane の余白・強調・名前ラベルの描き方が変更前と同じ
  （余白が同じなので端末の置き場の大きさも同じ）。
- [ ] AC2: 「分割時だけ」では、pane が 1 つの tab の pane に余白・強調・名前ラベルを描かず、分割された tab（zoom 中を含む）の
  pane には「常に」と同じ枠を描く。
- [ ] AC3: 「表示しない」では、分割の有無に関わらず、外周側の余白・強調・名前ラベルを描かない。
- [ ] AC4: 隙間を切ると、隣の pane と接する辺の余白が無くなる（外周側の辺は枠の設定どおり）。分割が入れ子でも、辺ごとに
  隣の有無が正しく判定される。
- [ ] AC5: 枠を描かず隙間が入のときは、隣の pane と接する辺にだけ余白が残る。
- [ ] AC6: 設定を変えると、ページを読み直さずに反映され、保存され、ページを読み直しても保たれる。別のウィンドウで変えた値・設定の再読み込み
  （`prefix+shift+r`）でも反映される。
- [ ] AC7: モバイルの 1 列表示（`MobileShell`）の描き方は変わらない。
- [ ] AC9: 余白を取る辺の太さは枠の太さ（`paneFrameThickness`）に従う（「表示しない」＋隙間入で残る隣接辺、
  「常に」＋隙間切で残る外周辺も同じ）。
- [ ] AC8: `docs/herdr-parity.md` の H23 行と `docs/verification.md` の外観の確認手順が、この変更に合わせて更新されている。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: 設定画面（`prefix+s`）の「表示」節に 2 つの設定がある。設定画面を閉じても値は保たれる
  （閉じる操作で取り消されない）。描画モードの近くに、枠を描かない pane では枠の右クリックの経路が無くなる旨の説明がある。
- [ ] AC-I2 確定 / 取り消し: 選んだ・切り替えた時点で確定し反映する（確定ボタンは無い。既存の外観設定と同じ）。取り消しは
  元の値を選び直すこと。
- [ ] AC-I3 キーボードだけで完結するか: 設定画面の中を Tab で 2 つの設定へ移り、描画モードは矢印キーで選べ、隙間は
  Space/Enter で切り替えられる（既存の太さのラジオ・入切のスイッチと同じ部品）。
- [ ] AC-I4 フォーカスの行き先: 選んだ・切り替えた後もフォーカスはその部品に留まる（設定画面が閉じたり他へ飛んだりしない）。
- [ ] AC-I5 既存の操作を妨げないか: 枠を描かない pane でも、選ばれている pane の枠（メニューボタン）は今までどおり Tab で
  止まり Enter 等でメニューを開ける。そこにフォーカスがあることが画面で見える（余白が無くても端末の下に隠れない）。
  設定の部品の上のキーは、既存の設定画面と同じく端末や prefix の経路へ漏れない。

## 未確定事項 / 確認したいこと

- 枠を描かない pane で、メニューボタンにフォーカスがあることをどう見せるか（余白が無いので今の見せ方〔余白の背景色〕が
  使えない）。design で決める。
- 隙間を切ったとき、隣と接する辺の選択の強調は見えなくなる（強調の線は余白の中に引くため）。herdr は共有した境界線の
  うち選ばれた pane に接する部分を強調色にする（`src/ui/panes.rs:481-495`）。Web 版で境界（`Splitter`）側に色を付けるかは
  design で決める。
