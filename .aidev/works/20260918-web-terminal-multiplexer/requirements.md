# 要件: Web ターミナルマルチプレクサ（herdr 相当）— MVP 基盤

## 背景 / 課題

- AI コーディングエージェント（Claude Code / Codex 等）を複数並行で走らせる開発が増えている。
  herdr（Rust 製・Apache-2.0〔訂正 D5〕）はこれをターミナル上で解決したマルチプレクサで、tmux 型の
  session / workspace / tab / pane に「どのエージェントが blocked / working / done / idle か」の把握を加えている。
- ただし描画先がターミナルであるため、次の制約がある。
  - 表現力：ドラッグ＆ドロップによるレイアウト操作や、セッション同士の関係をグラフとして見せる表現ができない。
  - 到達性：端末エミュレータと SSH が前提で、スマートフォン等から様子を見る・一言返す、が難しい。
  - 集約：複数マシンで動くエージェントを 1 画面で見渡すには、端末側の工夫が要る。
- そこで、**ビューを Web 画面にした herdr 相当のマルチプレクサ**を作る。製品全体は複数の work に分けて段階的に着地させ、
  本 work はその**基盤（MVP）**を担う。

## 目的 / ゴール

- **製品全体**: 複数ホスト上で動く AI エージェントのセッションを、ブラウザの 1 画面で
  状態把握・操作・相互連携の設定まで行える状態。herdr の機能は取りこぼしなく同等以上に揃っている。
- **本 work（MVP）**: 1 ホスト上の端末セッション群を、別マシンやスマートフォンのブラウザからも認証付きで、
  herdr と同じ操作感（workspace / tab / pane・エージェント状態・マウス操作・既定キー・ブラウザを閉じても継続）で扱える状態。
  あわせて、herdr の全機能について本製品での扱いが一覧で確定しており、後続 work の範囲が漏れなく決まっている状態。

## ユーザーストーリー

- US1: AI エージェントを並行運用する開発者として、複数のエージェントを workspace / tab / pane に並べて同時に動かしたい。
  なぜなら 1 画面で並行作業を見渡し、切り替えの手間なく指示できるから。（受け入れ: AC1, AC2, AC3, AC4, AC5）
- US2: 同開発者として、各エージェントの状態を一覧で見て、入力待ち（blocked）のものへすぐ移動したい。
  なぜなら止まったエージェントに気づかず時間を失うことを防げるから。（受け入れ: AC6, AC7）
- US3: 同開発者として、ブラウザを閉じてもエージェントが動き続け、開き直せば同じ画面に戻りたい。
  なぜなら長時間のタスクを、ブラウザを開き続けることに縛られず回せるから。（受け入れ: AC8, AC9, AC18）
- US4: 同開発者として、開発サーバや WSL で動くセッションに、別マシンのブラウザやスマートフォンから安全に接続したい。
  なぜなら席を離れてもエージェントを見守り、必要なら一言返せるから。（受け入れ: AC10, AC11, AC12, AC16）
- US5: herdr の利用者として、herdr と同じ既定キー操作とマウス操作で使いたい。
  なぜなら学習し直すことなく移行できるから。（受け入れ: AC13, AC14, AC-I1〜AC-I5）
- US6: 製品オーナー（本 PJ の依頼者）として、herdr の全機能が本製品でどう扱われるか（MVP / 後続 work / 非対応と理由）を一覧で確認したい。
  なぜなら「取りこぼしなく同等」を検証できる形にし、後続 work の抜けを防げるから。（受け入れ: AC15）

- 1 ホスト上で端末セッションを保持し続けるサーバ機能（ブラウザを閉じてもプロセスが継続する）
- サーバ再起動後のレイアウト復元（workspace / tab / pane の構成・作業ディレクトリ・フォーカス。プロセスは新しいシェルで復帰する）

- ブラウザ: Chrome / Edge 最新版、モバイルブラウザ

## 機能要件

- F1 セッション保持: サーバはブラウザの接続と独立に端末プロセスを保持し、全クライアントが切断してもプロセスは継続する。
- F2 構造: session → workspace → tab → pane の階層を持つ（herdr の概念に従う）。
  workspace・tab・pane は作成・切替・名前変更・閉じるができ、pane は右と下へ分割できる。
- F3 端末: pane は実際の端末として振る舞う（出力の描画・入力の送信・画面サイズの追従）。
- F4 エージェント状態: pane 内のエージェントを検出し、`blocked` / `working` / `done` / `idle` / `unknown` の 5 状態を判定する。
  workspace の状態は配下のエージェントから集約して示す。
- F5 サイドバー: workspace とエージェントの一覧を状態つきで表示し、選ぶと該当の pane へ移動する。
- F6 復元: 再接続したクライアントに、workspace / tab / pane の構成と各 pane の画面内容（スクロールバックを含む）を復元して表示する。
- F7 同時接続: 同じセッションへ複数のブラウザから同時に接続でき、どちらからも表示と入力ができる。
- F8 アクセス制御: 認証を通過したクライアントだけが、一覧の取得・画面の閲覧・入力の送信を行える。ネットワーク越しの通信は暗号化される。
- F9 キー操作: 既定で herdr 互換の prefix 方式（`Ctrl+B` の後に 1 キー）で MVP の全操作を行える。
  prefix とその直後の 1 キー以外の入力は端末へ届く。
- F10 マウス操作: herdr が提供するマウス操作のうち MVP 範囲の機能に対応するものを行える（一覧は research で確定）。
- F11 モバイル: モバイルブラウザから、一覧の確認・pane の切替・端末への入力（prefix 操作を含む）を行える。
- F12 機能棚卸し: herdr の全機能項目について、本製品での扱いを「MVP で対応 / 後続 work / 非対応（理由）」に分類した表を持つ。
- F13 再起動後の復元〔D7〕: サーバを停止して再び起動すると、workspace / tab / pane の構成・各 pane の作業ディレクトリ・フォーカスを復元する。
  元のプロセスは失われ、各 pane は保存された作業ディレクトリで新しいシェルとして起動する。

## 非機能要件 / 制約

- **ホスト OS**: Linux / WSL2 / Windows ネイティブの 3 環境で動作すること。
- **ブラウザ**: Chrome / Edge 最新版、モバイルブラウザ（対象の OS / ブラウザは未確定事項）。
- **セキュリティ**: 端末への入力はホスト上の任意のコマンド実行と等価である。したがって、認証を経ないアクセスは
  一切の操作を許さない。ホスト外から到達できる形で起動するときは、認証と通信の暗号化が必須。
- **応答性**: 同一 LAN での接続時に、キー入力から画面へ反映されるまでの追加遅延が体感できない水準
  （目安 p95 50ms 以内）。大量出力（ビルドログ等）が流れる pane があっても、他の pane とブラウザの操作が固まらない。
- **規模**: 1 セッションで少なくとも pane 16 個を同時に表示・操作できる。
- **状態反映**: エージェントの状態変化が一覧に反映されるまで 2 秒以内。
- **技術スタック**: TypeScript か Rust。両者のメリット・デメリットを比較して design で決める。
- **設計上の前提**: 後続の work（複数ホスト集約・外部操作 API・ノードによるオーケストレーション）を、
  基盤を作り直さずに載せられること。
- **ライセンス**〔訂正 D5〕: herdr は Apache-2.0（0.8.0 以降。research.md F12.1）。herdr の資産（状態判定ルール・コード等）を
  流用するときは、Apache-2.0 の条件（著作権表示・LICENSE・NOTICE の保持、変更した旨の明示）を守る。
  （旧記述「herdr（AGPL-3.0-or-later）のコードは流用しない」は、ライセンス変更前の情報に基づいていたため訂正した）

## 相互作用の受け入れ基準（UI を伴う work のみ）

対象の部品: サイドバー（workspace / エージェント一覧）、tab バー、pane（分割・境界）、prefix 待ち状態、
名前変更などの入力ダイアログ、ヘルプ（キー一覧）の表示、閉じる操作の確認。

- [ ] AC-I1 開く / 閉じる: 入力ダイアログとヘルプは、キー操作（prefix＋キー）とクリックのどちらでも開き、
  `Esc` または外側クリックで閉じる。確定せずに閉じたときは値が変わらない。
  prefix 待ちの状態は画面上で判別でき、`Esc` か一定時間の経過で解除される。
- [ ] AC-I2 確定 / 取り消し: 名前変更は `Enter` で確定、`Esc` で取り消して元の名前に戻る。
  実行中のプロセスがある pane / tab / workspace を閉じる操作は確認を挟み、取り消せば何も失われない。
- [ ] AC-I3 キーボードだけで完結するか: MVP の全操作（workspace / tab / pane の作成・切替・分割・リサイズ・名前変更・閉じる、
  サイドバーからの選択、ヘルプ）を、マウスを使わずに最初から最後まで行える。
- [ ] AC-I4 フォーカスの行き先: 新しく作った pane / tab / workspace にフォーカスが移る。
  サイドバーで選んだ後は選んだ pane にフォーカスが移る。ダイアログやヘルプを閉じると、開く前の pane にフォーカスが戻る。
- [ ] AC-I5 既存の操作を妨げないか: pane にフォーカスがある間、prefix とその直後の 1 キー以外の入力
  （`Ctrl+C` / `Ctrl+D` / `Esc` / `Tab` / 矢印 / `Alt` 付き等）はすべて端末へ届く。prefix キー自体を端末へ送る手段がある。
  pane 上のホイールはその pane だけに作用し（端末アプリがマウス入力を受け付けている場合はアプリへ届く）、
  ページ全体や他の pane をスクロールさせない。ブラウザが横取りするキー（`Ctrl+W` 等）でページを閉じてしまっても、セッションは失われない（AC8）。
