# 要件: キー割り当てを変え、prefix を使わない直接のキーも使えるようにする（herdr のキー設定）

## 背景 / 課題

本製品のキー操作は **prefix（`Ctrl+B`）の直後の 1 キー**に固定されている。

- prefix は `KeyRouter.ts` の `combo === "ctrl+b"`（`packages/web/src/keys/KeyRouter.ts:82`・`:108`）に**直に書かれている**。
- 各操作のキーは `keymap.ts` の `DEFAULT_KEYMAP`（`packages/web/src/keys/keymap.ts:23`）1 つで、prefix の後のキーだけを持つ。
  **prefix を押さずに 1 打で効くキーは 1 つも無い**。
- キー一覧（`prefix+?`）は表記を**文字列で直書き**している（`HelpDialog.vue:37-90`）。トースト「Ctrl+B ? でキー一覧」
  （`Toast.vue:36`）、通知の案内文の「prefix+s」（`NotificationController.ts:33`）、モバイルの Prefix ボタン
  （`ExtraKeys.vue:71-74` が `ctrl+b` を注入する）も同じ。

herdr は **prefix そのものを含む全操作のキーを設定で変えられ、1 つの操作に複数のキーを持てて、prefix を使わない直接のキー
（`ctrl+alt+h` など）も割り当てられる**（`docs/herdr-parity.md` の **H26**。herdr の `[keys]`。
`third_party` には無いが、同じ版 `da6bcd5` の `src/config/keybinds.rs`・`docs/versions/0.9.1/.../keyboard.mdx`・`configuration.mdx`）。
本製品ではどれもできない。

困ること:

1. **prefix `Ctrl+B` が手に合わない・他の道具とぶつかる**。tmux から来た人は `Ctrl+A` を使っていることが多く、
   端末の中の別の tmux・screen・エディタが `Ctrl+B` を使うと、どちらが先に受けるかの取り合いになる。
   変えられないので、使う側が我慢するしかない。
2. **頻繁な操作（pane の移動・tab の切替・分割）も、毎回 prefix の 2 打になる**。herdr は `ctrl+alt+h` のような
   直接のキーで 1 打にできるが、本製品にはその手段が無い。
3. **キーの案内が実際に追従しない**。仮にキーを変えられても、案内が `Ctrl+B ?` のままだと、案内どおりに押しても動かない。

## 目的 / ゴール

- **利用者が、このブラウザで prefix と各操作のキーを自分の手に合わせて変えられ、prefix を使わない直接のキーでも操作できる状態**。
- **変えたキーが画面のすべての案内（キー一覧・トースト・通知の案内文・モバイルの Prefix ボタン）に映り、案内どおりに押せば動く状態**。
- **変えすぎても、1 操作で既定に戻れる状態**（キーが 1 つも効かなくなる事故を、設定の画面から必ず戻せる形で防ぐ）。
- **何も変えなければ、今のキー操作が 1 つも変わらない状態**。

## ユーザーストーリー

- US1: tmux などで `Ctrl+A` を prefix にしている利用者として、**本製品の prefix も変えたい**。なぜなら、
  手が覚えているキーと違うと打ち間違えるし、端末の中で別の道具が `Ctrl+B` を使っていると取り合いになるから。
  （受け入れ: AC1, AC3, AC6, AC8, AC9, AC11, AC-I1, AC-I2, AC-I3, AC-I4, AC-I5）
- US2: 特定の操作（分割・tab の切替など）のキーを変えたい利用者として、**操作ごとにキーを付け替えたい**。
  なぜなら、既定のキーが自分の配列や他の道具の癖と合わず、毎日使う操作ほど負担になるから。
  （受け入れ: AC1, AC4, AC6, AC7, AC8, AC9, AC-I1, AC-I2, AC-I3, AC-I4, AC-I5）
- US3: pane や tab を頻繁に行き来する利用者として、**prefix を押さずに 1 打で操作したい**。なぜなら、
  移動のたびに 2 打だと、エージェントを何本も見張るときの往復が積もって遅いから。（受け入れ: AC5, AC6, AC10）
- US4: キー一覧を見て操作する利用者として、**案内が実際のキーと一致していてほしい**。なぜなら、
  案内が古いと、押しても動かず、どこが違うのかを探す手間が生じるから。（受け入れ: AC1, AC11）
- US5: 今のキーのまま使っている利用者として、**何もしなければ操作が変わらないでほしい**。なぜなら、
  更新のたびに体に染みたキーが黙って変わると、間違った操作（pane を閉じる等）を誤って起こしかねないから。（受け入れ: AC2）
- US6: 設定を試している利用者として、**衝突や打ち間違いで壊しても、すぐ戻したい**。なぜなら、
  キーを変える画面自体がキーの設定に影響されると、戻れなくなる不安から誰も触らなくなるから。
  （受け入れ: AC6, AC8, AC9, AC-I2）

AC12（回帰）・AC13（文書）・AC14（起票）はこの work の完了条件で、特定のストーリーに紐づかない。

## スコープ

### 対象

- **prefix の変更**（既定 `ctrl+b`）。
- **各操作の割り当ての変更**：prefix の後のキーと、直接のキー（prefix なしの 1 打）。1 つの操作に複数持てる。
  操作は現在 `DEFAULT_KEYMAP` に割り当てのある全操作（分割・pane の移動/入れ替え/巡回/閉じる/拡大/名前変更・
  resize モード・copy モード・tab の作成/切替/名前変更/閉じる・workspace の作成/名前変更/閉じる・worktree・設定・
  通知・navigate モードに入る・キー一覧・goto・サイドバー・切り離し）。
- **設定画面の新しい節「キー」**での編集（キーを押して取り込む）、検証（衝突・予約・使えないキー）、既定へ戻す。
- **保存はこのブラウザごと**（herdr のキー設定はクライアントの機器の設定。本製品の他の設定と同じ流儀）。
- **案内の追従**：キー一覧（`prefix+?`）・トースト・通知の案内文・モバイルの Prefix ボタン。
- herdr が文書で勧める **`ctrl+alt` の直接のキーの一式を 1 操作で足す**（herdr の `keyboard.mdx`「Going prefix-free」）。

### 対象外

- **navigate モード・resize モード・copy モードの「中」のキー**（herdr でも copy・resize の中は固定で、変えられるのは
  navigate の移動 6 キー `navigate_*` だけ）。本 work は「モードに入る」キーまで。中のキーは backlog に起票する（AC14）。
- **独自コマンドのキー**（herdr の `[[keys.command]]`。popup・shell・pane・plugin。サーバで任意のコマンドを走らせる
  仕組みが要り、権限の設計が別に要る。`docs/herdr-parity.md` H12 の後続）。
- **herdr にあって本製品に操作自体が無いもの**（前後の workspace への移動・直前の pane・tab の並べ替え・
  pane の resize の直接のキー・agent への番号ジャンプ・scrollback を `$EDITOR` で開く・設定の再読み込み）。
  操作を足す work であって、割り当てを変える work ではない。backlog に起票する（AC14）。
  `R`（reload_config）・`e`（edit_scrollback）は今の「後続」の案内のまま残す（別の操作に割り当てれば、そちらが優先）。
- **herdr 互換以外のプリセット**（tmux 風など。backlog の元の項目のうち、割り当ての変更・保存が済んだ後に残る部分）。
- **設定ファイル・再読み込み**（H25b）。本製品には利用者が書く設定ファイルが無い。
- **ブラウザ・OS が先に受けて画面に届かないキー**（`Ctrl+T`・`Ctrl+W`・`Ctrl+N` 等）を届くようにすること。
  届かないキーは取り込めないので割り当てられない。その旨を画面で案内する（AC-I5）。
- サーバ側の変更（キーはブラウザの中だけで完結する。サーバ・protocol は変えない）。

## 機能要件

- 各操作に **0 個以上の割り当て**を持てる。割り当ては「prefix の後のキー」か「直接のキー」のどちらか。
- prefix を押すと prefix モードに入り、**次の 1 打を操作に引く**（既存の状態機械を保つ：3 秒で解除・Esc で取り消し・
  割り当てのないキーは黙って捨てる・修飾キー単体は無視して待ち続ける・prefix をもう一度押すとそのキーを端末へ送る）。
- **直接のキー**は terminal モード（端末に入力が向いている通常の状態）で、端末にフォーカスがあるときも、サイドバー等に
  フォーカスがあるときも効く。効いたキーは端末へ届かない。copy・resize・navigate・ダイアログの中では効かない。
- 割り当ての**検証**は保存する前に行い、拒否した理由を利用者に示す。保存されている値を読むときも同じ検証を通し、
  検証を通らない値は**値ごとに**落として既定へ戻す。
- キー一覧・トースト・通知の案内文・モバイルの Prefix ボタンは、**同じ 1 つの現在の割り当て**から作る
  （案内用の別の表を持たない）。

## 非機能要件 / 制約

- **キー入力は端末の入力の最短経路**にある。割り当ての引きは、押すたびに表を作り直さず、割り当てを変えたときに一度だけ作る
  （押すたびの遅延を増やさない）。
- 既存の **IME の変換中は割り当てとして扱わない**、`keydown` 以外のイベントは無視する、といった規則を保つ。
- 画面の枠の色・状態の記号・キーボード操作の規範（フォーカス・ラベル）は、既存の設定画面と同じ水準を保つ
  （WCAG 2.1 の色のコントラスト・キーボードだけでの操作）。
- **ブラウザの差**：修飾キー付きの文字は環境で `event.key` が変わる（macOS の Option は別の文字に化ける・Windows の AltGr は
  Ctrl+Alt として届く）。**確かめられない環境がある**ので、割り当てに使えるのは「届いたキー」だけとし、
  確認できていない範囲は `docs/verification.md` に残す。
- 型・保存の形は、既存の設定（`wtm.prefs.v1`。`store/settings.ts`）と同じ所有者・同じ落とし方（値ごとに検証して落とす）に従う。

## 完了条件 (受け入れ基準)

- [ ] AC1: 設定画面に節「キー」があり（節は 5 つになる）、prefix と、操作ごとの現在の割り当て（prefix の後のキー・直接のキー）が一覧で見える。何も変えていなければ、一覧は今の `DEFAULT_KEYMAP` と同じ内容である。
- [ ] AC2: 何も変えていないとき、今のキー操作は 1 つも変わらない。prefix `ctrl+b`・全既定の割り当て・3 秒の時間切れ・Esc での取り消し・割り当てのないキーを黙って捨てる・prefix を 2 回押すと `\x02` が端末へ届く・修飾キー単体の無視・IME 変換中の素通し・`R`/`e` の「後続」の案内。
- [ ] AC3: prefix を変えられる。変えた後は新しい prefix で prefix モードに入り、**旧い prefix は端末へそのまま届く**。prefix を 2 回押すと、その prefix のキーそのものが端末へ届く。prefix に使えるのは、ctrl か alt を含むキーか F キー（どれも端末へ送れる形。meta〔Cmd・Win〕を含むキーは端末へ送る形が無いので、prefix にできない）。
- [ ] AC4: 操作の「prefix の後のキー」を追加・置き換え・削除できる。1 つの操作に複数持てる。変えた後、外したキーは何も起こさず（黙って捨てる）、新しいキーでその操作が動く。
- [ ] AC5: 操作に「直接のキー」（prefix なしの 1 打）を割り当てられる。使えるのは ctrl・alt・meta のいずれかを含むキーか F キー（修飾キーの無い文字・名前のあるキー〔tab・enter・矢印等〕・shift だけを付けたキーは、端末への入力を奪うので使えない）。端末にフォーカスがあるときもサイドバー等にあるときも効き、効いたキーは端末へ届かない。copy・resize・navigate モードとダイアログの中では効かない。
- [ ] AC6: 次の割り当ては拒否し、**理由を画面に示す**（保存も反映もしない）。(a) 同じ種類（prefix の後／直接）で、すでに別の操作が使っているキー（その操作の名前を示す）。(b) prefix と同じキーを prefix の後のキーにする組（prefix の後のキーを選ぶときも、prefix を選ぶときも。prefix を 2 回押すと端末へ送る規則と衝突する）。(c) prefix の後のキーとして Esc（取り消しの専用。**画面の取り込みでは Esc は取り込みの取り消しになる〔AC-I1〕ので理由は出ず、保存値の読み込みで落として記録する**）と `ctrl+shift+v`（貼り付けのショートカットが prefix の状態に関わらずルーターより先に取るので、割り当てても効かない。decisions D11）。(d) 直接のキーとして、修飾キーの無い文字・名前のあるキー・shift だけを付けたキー（修飾キー単体は、chord の途中なので取り込まず、次のキーを待ち続けて理由を示す）。(e) AltGr で別の文字に合成されるキー（文字の入力に使われている）。(f) 直接のキーとして `ctrl+shift+v`（貼り付けのショートカット）。(g) prefix と同じキーを直接のキーにする組（直接のキーを選ぶときも、prefix を選ぶときも）。
- [ ] AC7: tab の番号選択（`1..9`）は、範囲の割り当てとして扱う。1〜9 のどれか 1 つの数字を押すと、その修飾キーの組の 1〜9 全部が割り当てられる（herdr の `switch_tab = "prefix+alt+1..9"` と同じ。prefix の後のキーは修飾キーなしでもよく、直接のキーは修飾キーが要る）。範囲にできるのは数字のキーだけで、shift を伴うものは、キー配列によって別の記号になるので範囲にしない。
- [ ] AC8: 変更は即時に効き（保存ボタンを置かない・再読み込み不要）、**このブラウザに保存**されて再読み込み後も残る。保存された値が壊れていても（JSON でない・形が違う・未知の操作・不正なキー・検証に通らない衝突）、**値ごとに**落として既定へ戻し、残りは生かして起動する。
- [ ] AC9: 既定に戻せる。**操作ごと**・**prefix**・**すべて**。すべてを戻すときは、取り消せない操作なので確認を挟む。すべてを戻した結果は AC2 の状態と同じになる（操作ごと・prefix を戻すときは、既定のキーを別の操作が使っていれば、その分は戻さずに知らせる）。設定画面はキーの割り当てに依らず（サイドバーのメニュー・モバイルの上部バーから）開けるので、キーが効かなくなっても、そこから既定へ戻せる。
- [ ] AC10: herdr が文書で勧める `ctrl+alt` の直接のキーの一式（`ctrl+alt+h/j/k/l` で pane の移動、`ctrl+alt+[` / `]` で前・次の tab、`ctrl+alt+c` で新規 tab、`ctrl+alt+d` で右へ分割、`ctrl+alt+shift+d` で下へ分割、`ctrl+alt+z` で拡大）を、1 操作で足せる。prefix の後のキーはそのまま残る。すでに使われていて足せなかった分は、足さずに知らせる。
- [ ] AC11: キー一覧（`prefix+?`）は**現在の割り当て**を操作ごとに表示し（prefix の後は `prefix+…`・直接は `ctrl+alt+…`）、絞り込みもできる。トースト「Ctrl+B ? でキー一覧」・通知の案内文の「prefix+s」・モバイルの Prefix ボタンは、現在の prefix・割り当てに従う。キー一覧を開く操作の割り当てが空になっていても、キー一覧へ至る道（設定の画面）が残る。
- [ ] AC12: navigate・resize・copy モードの「中」のキー、マウスの操作、サーバの動作は変わらない。既存の単体テスト・E2E が通る。
- [ ] AC13: `docs/herdr-parity.md` の H26 を更新し（herdr との違い・対象外とその理由）、`docs/verification.md` に手で確かめる項目（Firefox・Safari・macOS の Option・Windows の AltGr・ブラウザが先に受けるキー）を足す。

## 相互作用の受け入れ基準（UI を伴う work のみ）

対象の部品は、設定画面の節「キー」（割り当ての一覧・キーを押して取り込む操作・既定へ戻す）。

- [ ] AC-I1 開く / 閉じる: 節は設定画面（`prefix+s`・メニュー・モバイルの上部バー）の中にある。割り当ての変更は「変更」「追加」を押して取り込み待ちに入り、**押したキーで確定するか、Esc で取り消して元のまま**。取り込み待ちは、別の行の操作・ダイアログを閉じる操作でも終わる（終われば元のまま）。
- [ ] AC-I2 確定 / 取り消し: 確定は**押したキーそのもの**（別の確定ボタンは置かない）。検証に通らなければ理由を示し、割り当ては変えない（取り込み待ちは終わる。ただし修飾キー単体は chord の途中なので、理由を示して待ち続ける）。取り消しは Esc。すべてを既定へ戻すときは確認を挟み、「やめる」で何も変えない。
- [ ] AC-I3 キーボードだけで完結するか: 節へ入り→行を選び→「変更」で取り込み→キーを押して確定→「削除」→「既定に戻す」まで、マウスなしで通せる。
- [ ] AC-I4 フォーカスの行き先: 取り込み待ちに入るとき、取り込み待ちであることを示す部品へ移る。確定・取り消し・検証の失敗のいずれで終わっても、**押したボタンへ戻る**（そのボタンが作り直されるときは、新しい割り当ての同じ役目のボタンへ）。削除したときは、同じ行の次の部品（無ければ「追加」）へ移る。
- [ ] AC-I5 既存の操作を妨げないか: 取り込み待ちの間に押したキーは、端末・prefix 状態・ブラウザの標準の動作へ**漏れない**（ダイアログの Esc で設定画面が閉じることも、prefix に入ることも、直接のキーの操作が起きることもない）。取り込み待ちでない間は、設定画面の Esc・Tab・Enter・Space は今までどおり。ブラウザが先に受けて画面に届かないキーは取り込めないことを、画面に一言で案内する。
