# 要件: workspace の自動の名前とサイドバーの git の情報を、最初の pane のいまの場所に追従させる

## 背景 / 課題

名前を付けていない workspace の**自動の名前**（20260921-workspace-auto-label）と、サイドバーの spaces 欄の 2 行目の **git の情報**
（ブランチ・ahead/behind。worktree の自動グループの判定にも使う——20260923-workspace-grouping）は、どちらも **workspace を開いた場所**
（`Workspace.cwd`）から決めている:

- 自動の名前: 作成・名前を空にして確定・復元のときに `Workspace.cwd` から決める（`packages/server/src/session/SessionService.ts:218`・`:264`・`:875`）。
- git の情報: 5 秒ごとの監視が `Workspace.cwd` で `git` を走らせる（`packages/server/src/git/GitInfoPoller.ts:60` の `probe(ws.cwd)`）。

そのため、workspace の中で別のリポジトリへ `cd` しても、名前も git の情報も開いた場所のまま変わらない。利用者は 1 つの workspace の中で
リポジトリを渡り歩くことがあり、サイドバーの名前とブランチが**いま作業している場所と食い違う**。

herdr（`herdrdev/herdr` の commit `da6bcd5969779bfe0396bcf89a8025d4375d611e`。`/workspaces/web-tn-multiplexer/scratchpad/herdr/`）は、
**最初の tab の根の pane のいまの場所**から名前と git の状態を決め直す:

- 名前: `src/workspace.rs:1031-1047` の `display_name_from_terminals`（付けた名前があればそれ、無ければ最初の tab の根の pane の場所から
  自動の名前）。
- git: `src/app/git_refresh.rs:117-135` の `workspace_git_refresh_items` が `resolved_identity_cwd_from`（`src/workspace.rs:1011-1020`。
  最初の tab の根の pane の場所。無ければ開いた場所）ごとにブランチ・ahead/behind・リポジトリの情報を取り直し、`src/app/actions.rs:1392-1440`
  の `apply_workspace_git_statuses` が、その間に場所が変わっていれば結果を捨てたうえで、自動の名前と git の状態を**同じ場所の結果として一緒に**
  入れ替える。
- 根の pane が閉じられたら、その tab の残りの pane の先頭が根になる（`src/workspace/tab.rs:519-524` の `promoted_root_if_needed`）。
- 場所が知らされる（OSC 7）と、すぐに取り直す（`src/app/api.rs:338-339` の `request_git_identity_refresh`）。

前の work は、名前だけを追従させると git の情報と食い違うので「両方をまとめて扱う別の work」として残した（`.aidev/works/20260921-workspace-auto-label/requirements.md`
の「対象外」・`.aidev/backlog/product-roadmap.md:345`）。これがその work。

本製品には pane の「いまの場所」を知る仕組みが既にある: エージェントの監視が pane ごとに前面プロセスの cwd（Linux）か、シェルが OSC 7 で
知らせた場所（macOS・Windows ネイティブ）を読み、`Pane.cwd` を更新し続けている（`packages/server/src/agent/AgentMonitor.ts:169-190`。
20260921-new-terminal-cwd が「いまの場所」として使っている仕組みと同じ出所。`docs/verification.md:55-62`）。

## 目的 / ゴール

- **サイドバーの workspace の名前（自動の名前のとき）と git の情報が、その workspace の最初の pane でいま作業している場所を表している状態**
  （`cd` した後も、どのブラウザでも、再読み込みなしで）。
- **名前と git の情報が互いに食い違わない状態**（どちらも同じ場所から決まっている）。
- **利用者が付けた名前は、場所が変わっても変わらない状態**（git の情報だけが追従する）。

## ユーザーストーリー

- US1: 1 つの workspace の中で複数のリポジトリを渡り歩く利用者として、**`cd` した先のリポジトリの名前とブランチがサイドバーに出てほしい**。
  なぜなら、いまは開いた場所の名前とブランチのままで、いま作業しているリポジトリとブランチをサイドバーで確かめられないから。
  （受け入れ: AC1, AC2, AC4, AC5, AC6, AC10）
- US2: workspace に名前を付けた利用者として、**`cd` しても付けた名前はそのままで、ブランチだけが追従してほしい**。なぜなら、付けた名前は
  自分で選んだ見出しで、場所で書き換わると付けた意味が無くなる一方、ブランチはいまの場所のものでないと役に立たないから。（受け入れ: AC3）
- US3: 名前を付けた workspace を自動の名前に戻す利用者として、**戻した名前がいまの場所の名前になってほしい**。なぜなら、戻した直後だけ
  開いた場所の名前になり、git の情報と食い違うと混乱するから。（受け入れ: AC7）
- US4: サーバを再起動する利用者として、**再起動の後も、止める前にいた場所の名前と git の情報で戻ってほしい**。なぜなら、再起動のたびに
  開いた場所の名前に一度戻ると、どれがどの workspace か見分けにくくなるから。（受け入れ: AC8）

## スコープ

### 対象

- 自動の名前の workspace の名前を、**最初の tab の最初の pane**（下の定義）のいまの場所から決め直すこと。
- サイドバーの git の情報（ブランチ・ahead/behind・worktree の自動グループの判定に使うリポジトリの情報）を、同じ場所から取ること。
- 名前を空にして確定したとき（自動の名前に戻す）と、復元のときの自動の名前も、同じ場所から決めること。
- `docs/herdr-parity.md` の該当行（H01b）と、利用者向けの文書（`docs/verification.md`）。

「最初の tab の最初の pane」: workspace の tab の並びの先頭の tab の、画面の並び（分割の木を左・上から順にたどった順）で先頭の pane
（ふつうは左上の pane）。その pane が閉じられた・動かされた・先頭の tab が閉じられた・並べ替えられたときは、そのときの先頭の pane が代わる。

### 対象外

- **開いた場所（`Workspace.cwd`）そのものは変えない**。新しい tab を開く場所の代わり（`SessionService.ts:392`）・worktree を開くときに既に開いているかの判定（`packages/web/src/actions/ActionDispatcher.ts:284`・`:304`）・
  `session.json` の `cwd` は今までどおり開いた場所を使う（herdr も開いた場所 `identity_cwd` を別に持ち、追従では書き換えない）。
  ~~worktree の一覧を取るリポジトリ（`WorktreeService.ts:98-101`）も開いた場所のまま~~——review ラウンド 1 で、メニューの出し分け（`ws.git`）と食い違うと
  分かり、worktree の一覧・作成・削除もいまの場所で行うよう対象に移した（decisions D10）。
- tab の名前（`cd` に追従しない。今までどおり）。
- 名前を付けた workspace の名前（追従しない。git の情報だけが追従する）。
- 「いまの場所」の分かり方そのもの（Linux は前面プロセスの cwd、macOS・Windows ネイティブは OSC 7 だけ——既存の仕組みと既知の制約をそのまま使う）。
- herdr の「根の pane」を id で覚え続けること（下の「非機能要件 / 制約」の herdr との違いを参照）。
- サイドバー以外の表示の変更（名前・git の情報を読む web 側の箇所は今までどおり `Workspace.label`・`Workspace.git` を読む）。

## 機能要件

- 自動の名前の workspace の名前は、最初の tab の最初の pane のいまの場所から、前の work と同じ規則（git の中なら根のフォルダ名、git の外なら
  フォルダ名・ホームなら `~`・フォルダ名の無い根ならパスそのもの）で決まる。
- サイドバーの git の情報は、同じ場所で取る。git の外へ移ったら git の情報は消える。
- 最初の pane の場所が変わったら、**数秒のうち**（下の「数秒のうち」）に名前（自動のとき）と git の情報の両方が新しい場所のものに変わる。
  新しい名前が決まるまでは前の名前のまま。場所が変わっていない間は、名前を決め直すためにファイルシステムへ問い合わせない（例外: 止まった・遅いファイルシステムのためにフォルダ名で
  代えた後は、監視のたびに決め直しを試みる。AC15）。
- 「数秒のうち」: pane の場所が監視に読まれてから（既存の監視の周期。最長 1 秒）、git の監視の周期（5 秒）以内。つまり `cd` から 6 秒以内。
- 名前と git の情報は、同じ場所の結果として反映する（途中でさらに場所が変わったら、古い場所の結果で上書きしない）。
- 名前を付けた workspace は、場所が変わっても名前を変えない。git の情報だけが追従する。
- 名前を空にして確定したら、その時点の最初の pane のいまの場所から自動の名前を決める。
- 復元のときは、保存されていた最初の tab の最初の pane の場所から自動の名前を決める（pane の場所は以前の版から `session.json` の pane の `cwd` として
  保存されている。保存の中にその pane が見つからない壊れた形なら、開いた場所）。
- 最初の pane が閉じられた・別の pane と入れ替わった・先頭の tab が閉じられた・並べ替えられたときは、新しい最初の pane の場所に数秒のうちに追従する。
- 名前・git の情報の変化は、同じサーバに繋いだほかのブラウザにも再読み込みなしで反映される。

## 非機能要件 / 制約

- 3 つの OS（Linux・macOS・Windows）で動く。macOS・Windows ネイティブでは「いまの場所」は OSC 7 で知らせた場所だけ（既存の既知の制約）。
  知らされなければ、最初の pane を開いた場所のまま（今までの振る舞いと同じ）。
- 名前を決める待ちの上限・止まったファイルシステムへの配慮（前の work の decisions D4）は、追従で決め直すときにも効く。
- `session.json` の形は変えない（以前の版・新しい版のどちらが読んでも壊れたファイルにしない）。
- git の問い合わせは、今の 5 秒ごとの監視に加えて、最初の pane の場所が変わったときに 1 回ずつ増えるだけにする。
- herdr との違い（受け入れる割り切り。対応表に書く）:
  - 「根の pane」: herdr は tab を作ったときの pane を覚え続け（入れ替え・移動をしても同じ pane）、閉じられたときだけ残りの先頭に代える。
    本製品は、そのときの画面の並びで先頭の pane を使う（入れ替え・端への移動で左上に来た pane が代わる）。
  - 「いまの場所」: herdr は OSC 7 で知らせた場所を先に、無ければシェルの cwd を使う。本製品は既存の仕組み（Linux は前面プロセスの cwd を
    先に、無ければ OSC 7）を使う。
  - 場所が変わってから名前が決まるまで: herdr は根を探す前にいったんフォルダ名を出す。本製品は決まるまで前の名前のまま（決まるのは上限つきで
    すぐ）。
