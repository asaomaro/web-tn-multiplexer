# 要件: 外観と設定の残り（サイドバー行・tab バー・pane 枠・設定の再読み込み）

紐づく charter ゴール: `.aidev/charter.md` は本リポジトリに無いため対象外。

## 背景 / 課題

20260918-web-terminal-multiplexer の research（herdr 棚卸し）で、backlog に無かった herdr の
機能群の1つとして「外観と設定」が追加された（decisions D8）。テーマ（H24。20260921-theme-settings）
は既に対応済みで、残るのは次の4つ（`docs/herdr-parity.md` H21〜H23・H25b。backlog「外観と設定の残り」）。

1. **サイドバーの workspace 行の並び**（H21）: `Sidebar.vue` の spaces 区画は、サーバから届く
   `session.workspaces`（`Map`）の反復順のまま表示され、並べ替えられない
   （`packages/web/src/store/session.ts:26,39,42`）。agents 区画には既に「グループ順/優先度順」の
   トグルがある（`Sidebar.vue:38-58`）のに、spaces 区画には無い。
2. **tab バーの見え方**（H22）: `TabBar.vue` は tab 数に関わらず常に描画され続け（`App.vue:48`）、
   tab が1個だけのときも画面の縦の領域を占め続ける。右端には「＋ 新しいタブ」ボタンしか無く、
   herdr が持つような状態表示（時刻等）は無い（`TabBar.vue:62-69`）。
3. **pane の枠・隙間・エージェント名表示**（H23）: 枠の太さ・pane 間の隙間は固定値
   `4px`（`PaneFrame.vue:133-136`・`Splitter.vue:122,126`）で、利用者は変えられない。
   pane ごとのエージェント名（`paneNameOf`）は既に計算されているのに、`aria-label` にしか
   使われておらず、画面上に可視のテキストとして出ていない（`PaneFrame.vue:40-45,99-113`）。
4. **設定の再読み込み**（H25b。herdr の `reload_config`）: `prefix+shift+r` はいま「未対応（後続:
   外観と設定）」の案内のままである（`packages/web/src/keys/keymap.ts:26`）。本製品には利用者が
   書く設定ファイルが無く、設定はブラウザの `localStorage`（`wtm.prefs.v1`）1本に集約されている。
   別のタブ・ウィンドウで変えた設定のうち、`storage` イベントで自動的に追従するのは `keyPrefs`
   （キー割り当て）だけ（`packages/web/src/store/settings.ts:181-193`）——`statusSymbols`・
   `scrollback`・`newCwdPolicy`・`theme` 系・`sidebarWidth`・`agentSort` 等は、別タブでの変更が
   ページの再読み込みまで反映されない。

## 目的 / ゴール

利用者がサイドバーの workspace 行の並びを好みに調整でき、tab バーが tab 数に応じて自動で
表示・非表示を切り替えて画面を広く使え、tab バーから現在時刻を確認でき、pane の枠・隙間の
太さと pane 上のエージェント名表示を好みに調整でき、別のタブ・ウィンドウで変えた設定を
キー操作1つで今の画面へ反映できる状態。

## ユーザーストーリー

- US1: 複数の workspace を並行して開く利用者として、サイドバーの workspace 一覧の並びを
  名前順にも切り替えたい。なぜなら、開いた順（サーバ側の作成順）のままだと、workspace が
  増えるほど目的のものを探しにくいから。（受け入れ: AC1〜AC3）
- US2: 1つの workspace・tab だけで作業することが多い利用者として、tab が1個のときは
  tab バーを自動で隠したい。なぜなら、tab を切り替える必要が無いのに常に一定の高さを
  占められると、端末に使える縦の領域が減るから。（受け入れ: AC4〜AC6, AC-I6）
- US3: 長時間 pane で作業する利用者として、tab バーの右端で現在時刻を確認したい。なぜなら、
  端末画面には時計が無く、いま何時か確かめるためだけに OS 側の時計へ視線を移す手間を省きたい
  から。（受け入れ: AC7〜AC8）
- US4: 複数の pane を並べて作業する利用者として、pane の枠の太さ・隙間を自分の好みに調整し、
  各 pane の上でどのエージェントが動いているか一目で見たい。なぜなら、既定の細い枠だと pane の
  境目が見づらいことがあり、エージェント名は `aria-label`（スクリーンリーダー向け）にしか
  無く画面では確認できないから。（受け入れ: AC9〜AC12）
- US5: 同じサーバを複数のタブ・ウィンドウで開いて使う利用者として、片方で変えた設定
  （テーマ・表示・端末の設定等）を、もう片方でも明示的なキー操作で読み込み直したい。
  なぜなら、いまは `keyPrefs` 以外の設定がページの再読み込みでしか揃わず、herdr の
  `reload_config`（`prefix+shift+r`）に相当する操作が「未対応」のまま残っているから。
  （受け入れ: AC13〜AC15）

## スコープ

### 対象

- workspace 一覧の並び順の選択肢を、既存の agents 区画の「グループ順/優先度順」と同じ UI 語彙
  （設定画面のトグル）で足す（既定は今までどおり「開いた順」）。
- tab バーの自動非表示：現在の tab（workspace 内の tab 一覧）が1個のときは tab バー自体を
  非表示にする。2個以上に増えたら再び表示する。**opt-in の設定は設けない**——常に有効
  （「非機能要件」で理由を述べる）。
- tab バーの右端に、現在時刻を表示する（herdr が挙げる「時刻・ホスト名・コマンド結果」の
  うち時刻だけを対象にする。理由は対象外節を参照）。
- pane の枠・隙間の太さを、設定画面から選べる何段階か（例: 細い・既定・太い）の選択肢にする。
- pane の枠にエージェント名を可視のテキストとして出す opt-in の設定（既定は無効。常時表示すると
  既存の見た目が変わるため）。
- `prefix+shift+r`（`reload_config`）に、「このブラウザの `localStorage`（`wtm.prefs.v1`・
  `wtm.seen.v1`）を読み直し、いま `storage` イベントで自動追従していない設定を今の画面へ
  反映する」操作を割り当てる。対象は**少なくとも** `statusSymbols`・`scrollback`・
  `newCwdPolicy`・`newCwdPath`・テーマ系・`sidebarWidth`・`sidebarCollapsed`・`agentSort`・
  `keyboardLockInFullscreen`（research 時点で `storage` 追従を持たないと確認済みの項目。
  「未確定事項」参照——research で洗い出しを確定させ、追加があれば design へ反映する）。
  `NOT_YET_BINDINGS` の案内をこの実装で置き換える。

### 対象外

- **独自トークン**（herdr の `$name` 相当。サイドバー行へ外部から値を差し込む仕組み）:
  research（20260918-web-terminal-multiplexer）の時点で「外部操作 API」work に切り出し済み
  （まだ着手していない別の backlog 行）。サーバ外部からの操作という別の仕組みが要るため。
- **サイドバー行の色の条件付け**（herdr の設定ファイルで書ける色のルール式相当）: 本製品には
  利用者が書く設定ファイルが無く、UI から任意の条件式を組み立てさせる仕組みは、既存の状態別の
  色分け（`StateIcon.vue`）を大きく超える設計判断（ルール言語・UI）を要する。この work の他の
  項目と比べて労力が不釣り合いに大きいため、既定の色分けのままとし、対象外にする。
- **tab バーの位置（上/下）の切り替え**: 既定で上固定の前提でレイアウト（`App.vue` の縦
  flex・モバイルの `MobileShell.vue` 等）が組まれており、位置を可変にすると影響範囲が
  サイドバー・モバイル双方に広がる。この work では「1個のときに隠す」「右端の時刻表示」に
  絞り、位置の切り替えは別 backlog 行の候補として残す。
- **tab バーの右端の状態表示のうち、時刻以外**（herdr が挙げる「ホスト名・コマンド結果」）:
  「コマンド結果」は本製品のサーバ・protocol 側に対応する情報が無く、対象外。ホスト名は、
  本製品が複数ホストをまたぐ構成（backlog「複数ホストの集約」）に未対応な現状では常に
  自分自身の1台なので、意味のある情報にならず対象外。**時刻**は対象（「対象」節を参照。
  ブラウザの `Date` から取れ、実装・検証のコストが低い。design で表示形式を決める）。
- **サーバ側の設定ファイル・設定の永続化の仕組みそのものの変更**: この work はブラウザの
  `localStorage` の**読み直し**だけを扱う。サーバ側に設定ファイルを持たせる設計変更は対象外
  （20260921-theme-settings の対象外整理と同じ理由）。
- **pane の枠の色・選択中以外の枠のスタイル変更**: 太さ・隙間の調整に絞り、色は
  20260920-ui-selection-visuals 等の別 work の対象（既存の配色トークンの衝突の話）と重複させない。
- **tab バー自動非表示の入切設定**: tab バーが1個のときに隠れる挙動そのものを無効にする
  opt-out は設けない。tab が1個しか無い間は、隠しても「切り替える」操作自体が意味を持たない
  （切り替え先が無い）ため、常にこの挙動にする方が単純で分かりやすいと判断した
  （「非機能要件 / 制約」を参照）。

## 機能要件

- 設定画面（`prefix+s`）の該当する節に、workspace 一覧の並び順トグルを足す（agents 区画の
  トグルと同じ場所・同じ見た目に揃える。design で具体的な節を決める）。
- tab が1個のときだけ `TabBar` を丸ごと非表示にする（`v-if` 相当）。2個以上に戻ったら表示に戻る。
  非表示の間も `prefix+c`（新規 tab）等の既存のキー操作・既存のマウス操作（サイドバーの
  workspace 行のクリック等）は変わらず使える。非表示になる瞬間に tab バーの中の要素へ
  フォーカスがあった場合は、既存の「フォーカスを失う操作」と同じ扱い（design で行き先を決める）。
- tab バーが表示されているとき、右端に現在時刻を表示する（1分ごと程度に更新。design で頻度・
  書式を決める）。
- 設定画面に pane の枠・隙間の太さの選択肢（何段階かの離散値）を足す。既定は今までの見た目
  （4px 相当）と変わらない。
- 設定画面に「pane にエージェント名を表示する」opt-in の switch を足す。有効にすると、
  エージェントが動いている pane の枠に、いまの `paneNameOf` の値を可視のテキストとして出す。
- `prefix+shift+r` に「設定を読み直す」操作を割り当てる。押すと、いま自動追従していない設定を
  `localStorage` から読み直し、画面に反映する。結果を一言（トースト等の既存の案内の仕組み）で
  知らせる。開いている workspace・tab・pane の構成やフォーカスの位置は変えない。

## 非機能要件 / 制約

- **tab バーの自動非表示だけは、意図的な既定挙動の変更**（今までは tab が1個でも常に表示 →
  この work の後は tab が1個のとき非表示）。他の項目（並び順・時刻表示・枠の太さ・
  エージェント名の可視表示・設定の再読み込みのキー割り当て）は、いずれも opt-in か
  「今まで割り当てが無かったキーへの新規割り当て」で、既定の見た目・挙動は変えない。
- tab バーの自動非表示は、既存のモバイル（`MobileShell.vue`）・デスクトップ双方のレイアウトを
  崩さない（design で両方の影響を確認する）。
- 「設定を読み直す」は、いま開いている画面の**状態**（開いている workspace・tab・pane の構成と
  フォーカスの位置）を変えない——**設定**（テーマ・表示・端末等の `wtm.prefs.v1` の値）だけを
  読み直す。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 並び順トグル・枠の太さの選択肢・エージェント名 switch は、いずれも
      設定画面の中の常設の部品（開閉の概念を持たない）。tab バー自体の自動表示・非表示は
      「開閉相当」の挙動だが、この work が新設する能動的な UI 操作ではなく tab 数という
      状態に連動する表示の切り替えなので、AC4〜AC6・AC-I6 で扱う（ここでは設定画面の部品だけを
      対象にする）。tab バーの時刻表示（AC7・AC8）は、開閉・確定・キーボード操作のいずれも
      伴わない受け身の表示なので、AC-I1〜AC-I5 の対象外（表示の有無自体は AC7 が扱う）。
- [ ] AC-I2 確定 / 取り消し: 並び順トグル・枠の太さの選択肢・エージェント名 switch・
      `prefix+shift+r` は、いずれも選んだ・押した瞬間に確定・保存する（既存の設定項目
      〔`statusSymbols` 等〕と同じ流儀。確認ダイアログは挟まない）。
- [ ] AC-I3 キーボードだけで完結するか: 設定画面の新しい部品（並び順トグル・枠の太さの選択肢・
      エージェント名 switch）は、既存のトグル・switch と同じ Tab 順・操作方法（Enter/Space・
      矢印キー等）で操作できる。`prefix+shift+r` は既存のキー割り当ての仕組みにそのまま乗るので、
      キーボードだけで完結する。
- [ ] AC-I4 フォーカスの行き先: 並び順トグル・枠の太さの選択肢・エージェント名 switch の
      いずれを選んでも、設定画面内のフォーカスは動かない（選んだ部品に留まる）。
- [ ] AC-I5 既存の操作を妨げないか: `prefix+shift+r` は、いま「未対応」の案内が出ていた操作を
      置き換えるだけで、他のキー割り当てとは衝突しない。
- [ ] AC-I6 既存の操作を妨げないか（tab バー）: tab バーの自動非表示は、既存のキーボードだけでの
      tab 操作（`prefix+n`/`prefix+p` 等）を妨げない。非表示になる瞬間に tab バー内の要素へ
      フォーカスがあった場合、フォーカスは失われず、既存の「フォーカスを失う操作の扱い」
      （設定画面を閉じたとき等と同じ考え方）に沿って行き先が決まる（design で具体的な行き先を
      決める）。

## 未確定事項 / 確認したいこと

- workspace の並び順トグルを置く場所（設定画面のどの節か。「表示」節に既存の agents 区画の
  トグルがあるかどうか含め、design で確認する）。
- pane の枠・隙間の太さの選択肢の段階数・具体的な px 値（design で決める）。
- 「設定を読み直す」が対象にする設定項目の完全な一覧（research で `settings.ts`・`view.ts`・
  `seen.ts` を洗い出し、`storage` イベントを持たない項目を網羅する）。
- pane 上のエージェント名表示の具体的な位置・スタイル（枠の内側の隅か、タイトル行のような
  帯を新設するか。design で決める。既存の pane の見た目・拡大表示・分割線との重なりを避ける）。
- tab バーが非表示になる瞬間、tab バー内の要素（新しい tab ボタン等）にフォーカスがあった
  場合の具体的な行き先（AC-I6。design で決める）。
