# 要件: pane 名表示を herdr の見た目に寄せ、ドラッグでの pane 入れ替えに対応する

紐づく charter ゴール: なし（`.aidev/charter.md` 未導入）。
`.aidev/backlog/product-roadmap.md` の既存項目「D&D による pane の分割 / 分割解除 / 移動（Web 固有の操作）」
（出典: `.aidev/works/20260918-web-terminal-multiplexer/requirements.md`）のうち、**「移動」の一部
（同一 tab 内での入れ替え）を先行して対応する**。分割・分割解除・別 tab/workspace への移動は対象外
（backlog に残す）。

## 背景 / 課題

pane 名の可視表示（20260922-appearance-settings-rest の `paneAgentNameVisible`）は実装済みだが、
利用者が herdr の実際の画面と見比べたところ、表示スタイルが herdr と異なっていた：

- 本製品（現状）: pane の左上角に、端末の内容に重ねる形の小さなバッジとして表示（`.pane-frame-name`。
  `PaneFrame.vue:177-192`）。
- herdr: 枠線に埋め込む形（legend 風）で表示し、フォーカス中の pane は枠・名前が強調色、
  フォーカスが無い pane は枠・名前とも薄い色になる。

見た目を herdr に寄せる過程で、利用者から「Web 画面であることを活かし、この名前ラベルを摘まんで
ドラッグし、pane を入れ替えられるようにしたい」という追加の要望が出た（herdr は TUI なのでこの操作は無い）。

## 目的 / ゴール

- pane 名の表示が、枠線に埋め込まれた legend のような見た目になり、フォーカス中/フォーカス無しが
  一目で分かる状態。
- 同一 tab 内の2つの pane について、一方の名前ラベルを摘まんでもう一方へドロップすると、
  その2つの pane が入れ替わる（レイアウト内の位置が交換される）状態。
- 既存のキーボードによる入れ替え（`prefix+…` の方向入れ替え。`pane.swap`）は変わらず使える状態
  （マウス操作を追加するもので、キーボードでの操作を置き換えない）。

## ユーザーストーリー

- US1: 複数 pane を並べて作業する利用者として、どの pane が今フォーカスされているかを、
  枠と名前の見た目だけで一目で見分けたい。なぜなら、pane 数が増えるほど「今どこを操作しているか」を
  見失いやすいから。（受け入れ: AC1〜AC3）
- US2: マウス/トラックパッド/タッチ操作でレイアウトを組み替えたい利用者として、pane の名前ラベルを
  ドラッグして別の pane へドロップするだけで、2つの pane を入れ替えたい。なぜなら、方向キーでの
  入れ替えは隣接する pane同士でしか使えず、離れた pane 同士を入れ替えるには何度も操作する必要があり、
  Web アプリならではの直接操作の方が速いから。（受け入れ: AC4〜AC7, AC-I1〜AC-I5）

## スコープ

### 対象

- `PaneFrame.vue` の名前ラベルの見た目を、枠線に埋め込む legend 風に変更する。
- フォーカス中/フォーカス無しで、枠・名前の配色を変える（フォーカス中は既存の強調色を流用、
  フォーカス無しは薄い色を新設）。
- 名前ラベルをポインタ操作（マウス）で摘まみ、**同一 tab 内**の別の pane へドロップすると、
  2つの pane がレイアウト内で入れ替わる。
- ドラッグ中の視覚的フィードバック（ドラッグ中であることが分かる・ドロップ先候補が分かる）。
- ドロップ操作の失敗時（範囲外・同じ pane へドロップ・無効な対象）は何も起きない（現状維持）。

### 対象外

- 別 tab・別 workspace への pane の移動（backlog の同項目のうち「移動」の残り。ドラッグで tab バーや
  サイドバーへドロップする経路は対象外のまま）。
- pane の分割・分割解除をドラッグで行うこと（同じ backlog 項目の別要素。対象外）。
- タッチ操作でのドラッグ（`PaneFrame` の枠・名前表示はデスクトップ限定〔`enabled` prop〕であり、
  モバイルの `MobileShell` は元々この機能を使わない。対応するモバイル向け操作は別途）。
- 名前が無い pane（`paneAgentNameVisible` が off、または名前を導出できない）でのドラッグ操作
  （名前ラベルが表示されていなければ掴む取っ手が無い）。

## 相互作用の受け入れ基準（UI を伴う work）

- [ ] AC-I1 開始: 名前ラベルの上でポインタを押し下げてから一定量動かすとドラッグが始まる
  （クリック〔メニューを開く操作〕と誤認しない閾値を設ける）。
- [ ] AC-I2 確定 / 取り消し: 有効な pane の上でポインタを離すと入れ替えが確定する。範囲外・
  無効な対象（同じ pane 自身・pane 以外の要素）で離す、または Esc を押すと取り消され、
  レイアウトは変化しない。
- [ ] AC-I3 キーボードだけで完結するか: ドラッグによる入れ替えはマウス操作の追加であり、
  キーボードでの代替（既存の `prefix+…` の方向入れ替え）が引き続き使えることを確認する
  （新しい操作をキーボードで完結させる要求ではない）。
- [ ] AC-I4 フォーカスの行き先: 入れ替えを確定すると、ドラッグした pane（元の場所から動いた方）に
  フォーカスが残る（`view.focusedPaneId` は同じ pane id を指したまま。位置だけが変わる）。
- [ ] AC-I5 既存の操作を妨げないか: 名前ラベルの上でのドラッグ以外の操作（枠の押下でのフォーカス・
  右クリックでのメニュー・端末そのものへのマウス操作）に影響しないこと。ドラッグの開始判定の
  閾値により、名前ラベルの単純なクリックは従来どおり素通りする（メニューを開く枠のクリック領域と
  重なるが、名前ラベル自体はクリックで何かを起こさないので新たな副作用は無い）。

## 完了条件 (受け入れ基準)

- [ ] AC1: `paneAgentNameVisible` が有効なとき、pane の枠に沿った境界線が常に見え、名前がその境界線に
  埋め込まれた見た目（legend 風）で表示される。
- [ ] AC2: フォーカス中の pane は境界線・名前が強調色（既存の `--wtm-pane-current` 系統の色）で表示される。
- [ ] AC3: フォーカスの無い pane は境界線・名前が薄い色で表示される。
- [ ] AC4: 同一 tab 内で、pane A の名前ラベルを pane B の上へドラッグ＆ドロップすると、pane A と
  pane B がレイアウト内の位置を交換する（`Layout.swap` の意味と同じ）。
- [ ] AC5: 交換後、分割の比率（`ratio`）はそれぞれの split の位置に residing したままで、
  内容（端末のプロセス）だけが入れ替わる（既存の `pane.swap` と同じ意味論）。
- [ ] AC6: 同じ pane 自身へドロップした場合・pane 以外の場所へドロップした場合は何も起きない。
- [ ] AC7: 複数のブラウザクライアントが同じ tab を見ているとき、一方が行った入れ替えがもう一方にも
  反映される（既存の `layout.updated` イベント配信の仕組みをそのまま使う）。

## 非機能要件 / 制約

- 既存の `pane.swap`（方向ベースの入れ替え）の挙動・RPC は変更しない（別の新しい方式を追加する）。
- ドラッグの実装は、このコードベースの既存の慣習（`Sidebar.vue`・`Splitter.vue` が使う Pointer Events）
  に合わせる（HTML5 Drag and Drop API は使わない。理由は design で述べる）。

## 未確定事項 / 確認したいこと

- ドラッグ中の視覚的フィードバックの具体的な見た目（ドロップ先候補のハイライト方法等）は design で決める。
- 新しい RPC 方式の名前・パラメータ形（例: `pane.swap_with`）は design で決める。
