# 決定記録

## D1: 代わりの場所を「以前と同じ場所」の 1 つにそろえ、requirements の AC9 を直した

- 背景: requirements（承認済み）は、いまの場所が分からないとき（AC5）は「以前と同じ場所」、指定した場所が使えないとき（AC9）は
  「サーバを起動した場所」と、代わりの場所を 2 つ持っていた（research の申し送り）。
- 決定: どちらも「以前と同じ場所」（workspace はサーバを起動した場所、tab はその workspace の場所、分割は元の pane の記録された場所）に
  そろえ、requirements の機能要件と AC9 を直した（design D3）。
- 理由 / 代替案: workspace では 2 つは同じ。tab と分割では「以前と同じ場所」のほうが利用者の予想に近く（その workspace・pane の場所）、
  サーバの実装も代わりの場所を 1 つだけ受け取ればよい。退けた案: AC9 のまま「起動した場所」——tab を開いただけで workspace と
  無関係な場所に出る。
- 影響: requirements の AC9 の文言。知らせるかどうか（AC5 は知らせない・AC9 は知らせる）は変えていない。

## D2: 方針はブラウザごとの設定にした（herdr はサーバ側の設定）

- 背景: herdr の `terminal.new_cwd` はサーバ側の設定（1 人で使う前提。research F19）。本製品は複数のブラウザから繋がる。
- 決定: 設定ダイアログの「端末」の節に置き、要求のたびに方針と元の pane を載せる。場所を決めるのはサーバ（design D1・D2）。
- 理由 / 代替案: 直前の work で「このブラウザの設定」をそろえたところで、端末ごと（携帯・母艦）に変えられ、サーバを起動し直さずに変えられる。
  退けた案: `wtm serve --new-cwd`——変えるたびに起動し直しで、全ブラウザに効く。どちらにしても、元の pane をサーバは知らない
  （research F16）ので protocol に足すものは要る。
- 影響: protocol に `newCwd` を足す。herdr の対応表（H36b）に「置き場所が herdr と違う」と書く。

## D3: architecture 工程は挟まない

- 背景: autonomous では protocol.md「4.5」の条件に当たれば architecture を自動で挟む。この work は protocol・server・web をまたぐ。
- 決定: 挟まない。
- 理由: またぐが、**責務の向きは今のまま**（web が要求し、サーバが決めて起動する）で、新しい責務の分割は `session/newCwd.ts` 1 つだけ。
  design の「インターフェース」で型と関数の形まで決めてあり、tasks で分解できる。
- 影響: tasks は design から直接分解する。

## D4: 「いまの場所が分からない」ときは元の pane の記録された場所で開く（requirements の AC5 を直した）

- 背景: design の点検（must）が、`Pane.cwd` は必ず値を持つ（起動した場所が入り、エージェントの監視が追従させる）ので、元の pane が
  ある限り「記録も無い → 以前と同じ場所」には決してならない、と指摘した。requirements の AC5 は「いまの場所が分からない」ときも
  「以前と同じ場所」と書いていた。
- 決定: 「いまの場所が読めない」ときは記録された場所で開き、「以前と同じ場所」で開くのは元の pane が無いときだけにする。
  requirements の機能要件と AC5 を直した（design D4）。
- 理由 / 代替案: 記録された場所は herdr の「元の pane を引き継ぐ」に最も近く、macOS・Windows でもシェルが OSC 7 を出していれば追従している。
  退けた案: 記録を使わず以前と同じ場所へ——前面の cwd を読めない OS では「引き継ぐ」がまったく効かなくなる。
- 影響: requirements の AC5。知らせない点は変えていない。

## D5: 知らせる範囲を「引き継ぐ」以外のすべての方針に広げた

- 背景: requirements の AC9 は「指定した場所」が使えないときに知らせることを求める。ホーム・起動した場所が使えない場合は書いていない。
- 決定: 「引き継ぐ」以外の方針で代わりへ回したときは、すべて知らせる（design D9）。知らせるかどうかはサーバが `cwdFallback` で決める。
- 理由: 利用者が選んだ方針が効かなかったことに変わりはなく、知らせないと理由が分からない。AC9 の要求（指定した場所では必ず知らせる）には反しない。

## D6: T10（テストの実行と記録）は test 工程で消化し、E2E の一式は deliver の直前に回す

- 決定: T10 は coding の承認時に未チェックのまま残し、test 工程で単体一式と影響を受ける E2E の spec を走らせて記録する。
  E2E の一式は deliver の直前に 1 回（利用者の指示「少しの修正ですべて回すのは時間とみあいません」）。
- 理由: `aidev-30-tasks` 手順6。前の work（`20260921-herdr-settings-gaps` の decisions D4）と同じ扱い。
