# 要件: workspace のグルーピングと並べ替え

紐づく charter ゴール: なし（`.aidev/charter.md` 未導入。herdr 対応表 H04（workspace の並べ替え部分）・
H37（worktree グループの部分。手動グループは herdr に前例が無い独自機能——後述「対象」参照）・
backlog「workspace のグルーピング」に基づく。H21〔既存の「開いた順/名前順」ソートトグル〕は別物で
本 work の対象外——「対象外」節参照）

## 背景 / 課題

`20260918-web-terminal-multiplexer` の research ゲート（decisions.md D6）で、backlog
「workspace のグルーピング」は次の3つを1つの work として扱うと決めた：

1. herdr 同等の Git worktree グループ（同じリポジトリの本体＋worktree を自動的に束ねる。H37）
2. 利用者による任意の束ね（herdr には無いこの製品独自の機能）
3. workspace・tab の並べ替え（H04）

このうち **tab の並べ替えは `20260923-missing-keybinding-actions` で既に実装済み**
（`move_tab_previous`/`move_tab_next`・protocol `tab.move`）。worktree の**作成・一覧**は
`20260920-git-worktree-actions` で済んでいる（`docs/herdr-parity.md` H37）。本 work は残り——
**workspace の並べ替え**・**worktree の自動グループ化**・**任意の束ね（手動グループ）**を実装する。

`packages/protocol/src/model.ts` の `Workspace.groupId: string | null` は、この work のために
既に予約されているフィールドだが、常に `null` で実際には使われていない（research.md F1）。

herdr のグループ化は完全に自動（git の共通ディレクトリが同じ workspace を束ねるだけで、利用者が
手動でグループを作る API は存在しない。research.md F3）。**「任意の束ね」は herdr に前例が無い、
この製品独自の拡張**であるため、実装は herdr を模倣せず独自に設計する（利用者との協議で
「名前付きグループ」の形に確定。decisions.md D1）。

## 目的 / ゴール

- 同じ Git リポジトリの複数 workspace（本体＋worktree）が2つ以上あるとき、サイドバーで自動的に
  束ねて表示され、折りたたみ・展開ができる状態。
- 利用者が任意の workspace を名前付きグループへ手動でまとめられ、サイドバーで折りたたみ・展開できる
  状態。
- workspace の並び順を、ドラッグ＆ドロップとキーボードの両方で変えられる状態。グループ
  （worktree グループ・手動グループとも）はまとめて1つの単位として並べ替えられる状態。
- worktree グループの本体を閉じるとき、束ねられた worktree も一括で閉じられる状態（任意選択）。

## ユーザーストーリー

- US1: 複数の worktree を並行して開く利用者として、それらが同じリポジトリのものだと一目で
  分かる形でサイドバーに表示されてほしい。なぜなら、workspace が増えるほどサイドバーが読みにくく
  なり、どれがどのリポジトリの worktree か探す手間が増えるから。（受け入れ: AC1〜AC3）
- US2: プロジェクトやタスク単位で複数の workspace（worktree とは限らない）をまとめて管理したい
  利用者として、自分で名前を付けたグループへ workspace を出し入れしたい。なぜなら、関連する
  workspace をサイドバー上でまとめて見渡せると作業の切り替えが速くなるから。（受け入れ: AC4〜AC6）
- US3: 自分の作業の流れに合わせて workspace の並び順を変えたい利用者として、ドラッグでも
  キーボードでも並べ替えたい。なぜなら、マウスの届く範囲で素早く動かしたい場面と、キーボードだけで
  操作を完結させたい場面の両方があるから。（受け入れ: AC7, AC8, AC-I3）
- US4: グループ化した workspace をまとめて動かしたい利用者として、グループ全体を1つの単位として
  ドラッグで並べ替えたい。なぜなら、メンバーを1つずつ動かすのは手間で、グループとしてのまとまりを
  保ったまま位置を変えたいから。（受け入れ: AC9）
- US5: worktree の本体を片付けるとき、束ねられた worktree も一緒に片付けたい利用者として、
  本体を閉じる操作に「束ねた worktree も一緒に閉じる」選択肢がほしい。なぜなら、本体だけ閉じて
  worktree が散らばった状態を毎回手動で片付けるのは手間だから。（受け入れ: AC10）

## スコープ

### 対象

- **worktree 自動グループ**: workspace の cwd から Git の共通ディレクトリ（`git rev-parse
  --git-common-dir`。`WorktreeService` が worktree 作成時に既に使っている情報と同じ種類）を求め、
  同じ共通ディレクトリを持つ workspace が2つ以上あるときだけサイドバーで束ねて表示する
  （herdr と同じ「1人しかいなければ束ねない」ルール。research.md F3）。折りたたみ・展開ができる。
- **手動グループ**: 利用者が名前付きグループを作成し、任意の workspace を追加・グループから外せる
  （workspace 自体を消すわけではない。「削除」という語はグループ自体を消す操作にだけ使う——下記）。
  グループの作成・名前変更・削除ができる。サーバ側に永続化する（ブラウザを閉じても残る。
  `Workspace.groupId` を実際に使う設計にする——グループ自体の実体〔id・名前〕は design で
  データ構造を確定する）。折りたたみ・展開ができる。
- **workspace の並べ替え**: ドラッグ＆ドロップ（sidebar 上で workspace の行をつまんで動かす。
  `20260923-pane-name-dnd-swap` で確立したポインタドラッグの流儀を踏襲）と、キーボード操作
  （`move_workspace_previous`/`move_workspace_next` 相当の新しい `ActionId`。`move_tab_previous`/
  `move_tab_next` と同じ形）の両方で並び順を変えられる。
- **グループの一括移動**: worktree グループ・手動グループとも、グループ全体（親＋メンバー）を
  1つの単位としてドラッグで並べ替えられる（herdr の `WorkspaceMoveBlockParams` 相当。
  research.md 参照）。
- **グループの一括クローズ**: worktree グループの本体（グループの親）を閉じるとき、束ねられた
  worktree も一括で閉じる選択肢を設ける（herdr の `close_group` 相当）。

### 対象外

- worktree の削除（`git worktree remove`）: 別の backlog 項目
  （`.aidev/backlog/product-roadmap.md`「worktree の削除」）で扱う。本 work では触れない。
- 手動グループの色分け・アイコン等の高度な視覚カスタマイズ: 今回は名前だけを持つ最小限のグループ。
- tab の並べ替え: `20260923-missing-keybinding-actions` で対応済み。
- 既存の「開いた順/名前順」ソートトグル（H21・`view.workspaceSort`）自体の変更: 既に実装済みの別機能。
  グループ導入後もこのトグル自体は変えない（トグルとグループの並び順との関係は「未確定事項」参照）。

## 機能要件

- 同じ Git 共通ディレクトリを持つ workspace が2つ以上あるとき、サイドバーで自動的に1つの
  グループとして表示されること（本体が先頭、worktree がその下に束ねられる。herdr と同じ並び。
  research.md F3）。
- worktree グループ・手動グループとも、グループの行にクリックで開閉できる折りたたみアイコンが
  あること。折りたたみ中も、フォーカス中の workspace がそのグループの中にあれば、その行だけは
  見える（herdr と同じ挙動。research.md F3）。
- 利用者は、サイドバーの操作（右クリックメニュー等、既存の操作系に揃える）から新しい名前付き
  グループを作成できること。既存の右クリックメニュー（`ContextMenu`）はキーボードだけでも開いて
  操作できる作り（`20260920-git-worktree-actions` 等、既存の workspace メニューと同じ経路）なので、
  この経路に揃えることで AC-I3（キーボードだけで完結するか）を満たす。
- 利用者は、workspace を既存の手動グループへ追加・グループから外せること（この操作も同じメニュー
  経路で、キーボードだけで到達できること）。
- 利用者は、手動グループの名前を変更・グループ自体を削除できること（削除してもメンバーの
  workspace 自体は消えない。この操作も同じメニュー経路で、キーボードだけで到達できること）。
- workspace の行をドラッグして、サイドバー内の任意の位置へ並べ替えられること。
- キーボード操作（新しい `ActionId` 2つ）で、フォーカス中の workspace を前後へ1つずつ動かせること。
- グループの行（ヘッダー相当）をドラッグすると、グループ全体が1つの単位として動くこと（メンバーの
  内部順序・グループとしてのまとまりは保たれる）。
- worktree グループの本体を閉じる操作で、束ねられた worktree も一括で閉じるかどうかを選べること。

## 非機能要件 / 制約

- **既存動作の非破壊**: グループ化されていない workspace の一覧・切り替え・作成・削除・既存の
  並び順トグル（「開いた順」「名前順」。`view.workspaceSort`）の動作に変化がないこと
  （「開いた順」とグループ内の並び順・グループ自体の並び順の関係は design で確定する）。
- **手動グループの永続化**: サーバ全体で共有される情報（`session.json` の一部として保存。
  ブラウザ・タブをまたいで同じ状態が見える。`20260923-agent-session-resume` の連携設定が
  サーバ全体で共有される設計と同じ考え方）。
- **worktree 自動グループの折りたたみ状態**: herdr は client 側の preferences に持つ
  （research.md F3）。本製品もブラウザごとの設定として扱う（既存の `sidebarCollapsed` 等と同じ
  `localStorage` の流儀。design で確定）。
- **herdr との差異の記録**: 手動グループは herdr に前例が無い独自拡張であることを
  `docs/herdr-parity.md` に明記する。

## 相互作用の受け入れ基準（UI を伴う work）

- [ ] AC-I1 開く/閉じる: グループの折りたたみ・展開はクリックのトグルアイコンで行い、状態は
  即座に反映される。
- [ ] AC-I2 確定/取り消し: ドラッグでの並べ替え・グループ化操作は、ドロップで確定する。範囲外への
  ドロップ・Esc での取り消しでは何も変わらない（`20260923-pane-name-dnd-swap` requirements の
  取り消しに関する受け入れ基準と同じ流儀）。
- [ ] AC-I3 キーボードだけで完結するか: workspace の並べ替え・手動グループの作成/追加/削除/
  名前変更/削除は、マウス無し（キーボードだけ）でも一通り到達・完結できる。
- [ ] AC-I4 フォーカスの行き先: 並べ替え・グループ化操作の後、操作対象の workspace（またはその
  workspace が今 focus されていればその pane）にフォーカスが残ること。
- [ ] AC-I5 既存の操作を妨げないか: 本機能の追加が、サイドバーの既存の操作（workspace の切替・
  右クリックメニュー・並び順トグル・agents 区画）の操作性に影響しないこと。

## 完了条件 (受け入れ基準)

- [ ] AC1: 同じ Git 共通ディレクトリを持つ workspace が2つ以上あるとき、サイドバーで自動的に
  1つのグループとして表示される。
- [ ] AC2: 該当する workspace が1つしか無ければ、グループとして束ねられない（単独の行のまま）。
- [ ] AC3: worktree グループは折りたたみ・展開できる。折りたたみ中でも、その中に focus 中の
  workspace があれば見える。
- [ ] AC4: 利用者は名前付きの手動グループを作成できる。
- [ ] AC5: 利用者は任意の workspace を手動グループへ追加・グループから外せる。グループの名前変更・
  削除ができる（削除してもメンバーの workspace は残る）。
- [ ] AC6: 手動グループも折りたたみ・展開でき、状態はサーバに永続化されブラウザを閉じても残る。
  worktree グループと同じく、折りたたみ中でもその中に focus 中の workspace があればその行だけは
  見える（機能要件「グループの行にクリックで開閉できる折りたたみアイコン」参照）。
- [ ] AC7: workspace の行をドラッグして、サイドバー内の任意の位置へ並べ替えられる。
- [ ] AC8: 新しいキーバインド操作で、フォーカス中の workspace を前後へ1つずつ動かせる。
- [ ] AC9: グループ（worktree グループ・手動グループとも）の行をドラッグすると、グループ全体が
  1つの単位として動く。
- [ ] AC10: worktree グループの本体を閉じるとき、束ねられた worktree も一括で閉じる選択肢がある。
  選ばなければ本体だけが閉じる（現状の挙動のまま）。
- [ ] AC11: グループ化されていない workspace の一覧・切り替え・作成・削除・既存の並び順トグルの
  動作が既存のまま壊れていない（回帰なし）。

## 未確定事項 / 確認したいこと

- 手動グループと worktree 自動グループが重なったとき（同じ workspace が両方の対象になりうるか）の
  表示・優先順位は design で確定する。
- 「開いた順」「名前順」の既存トグルと、グループ自体の並び順・グループ内の並び順の関係
  （グループが常にトグルより優先されるか、トグルがグループ内の並びにも適用されるか）は design で
  確定する。
- `workspace.move`（新規 protocol メソッド）の params の形（`tab.move` と同じ `{id, direction}` か、
  ドラッグ操作の「どこへドロップしたか」を素直に表す形か）は design で確定する。
