# 要件: 色の個別の上書き（herdr の `[theme.custom]` 相当）

## 背景 / 課題

herdr は設定ファイルの `[theme.custom]`（と明暗別の `.light`/`.dark`）で、選んだテーマの個々の色（アクセント・パネルの背景・状態の色など）を
1 つずつ上書きできる。20260921-theme-settings では「本製品には利用者が書く設定ファイルが無い」ことを理由にこの機能を対象外にし、
`.aidev/backlog/product-roadmap.md` に起票した（H26 と同じ、herdr 対応済みの直後に残された「settings 機能の不足」の 1 つ）。

紐づく charter ゴール: なし（`.aidev/charter.md` は本リポジトリに無い）。

## 目的 / ゴール

herdr のテーマを一通り気に入っているが、特定の色（例：アクセントだけ・サイドバーの選択行の背景だけ）が読みにくい・好みでない利用者が、
**その色だけ**を変えられる状態にする。全体のテーマを選び直す必要が無く、変えた値はそのブラウザに残り、既定のテーマの更新（今後
テーマの計算式が直っても）を妨げない状態。

## ユーザーストーリー

- US1: herdr の複数の環境（明るい端末・暗い端末）を行き来する利用者として、明るいときと暗いときで別々に色を上書きしたい。なぜなら、
  読みにくい色が明暗のどちらか一方だけで起きることがあるから（受け入れ: AC1, AC3, AC4）。
- US2: 特定の色（例：状態の色・アクセント）が自分の環境で見分けにくい利用者として、その 1 色だけを変え、ほかは既定のテーマのままにしたい。
  なぜなら、テーマ全体を選び直すと気に入っている他の色まで変わってしまうから（受け入れ: AC2, AC5, AC6）。
- US3: 一度上書きした後に元へ戻したい利用者として、色ごと・すべてまとめて既定へ戻せるようにしたい。なぜなら、試してみて気に入らなければ
  すぐに元通りにしたいから（受け入れ: AC7, AC-I2）。

**AC8〜AC12・AC-I1・AC-I3・AC-I4・AC-I5 は、どのユーザーストーリーにも直接紐づかない基準**（それぞれ：AC8＝保存の規約、
AC9＝起動直後のちらつき防止、AC10＝docs の更新、AC11＝backlog の消し込み、AC12＝入力の説明、AC-I1＝開閉の操作性、
AC-I3＝キーボードだけの操作性、AC-I4＝フォーカスの行き先、AC-I5＝既存操作を妨げないこと）。ストーリーに紐づかない基準は
完了条件にそのまま並べてよい（`aidev-10-requirements` の書き方の指針）。

## スコープ

### 対象

- 設定画面の節「テーマ」に、上級者向けの上書き（`<details>` で折りたたみ）を足す。既存の「OS の明暗に合わせる」（自動切替）・
  テーマの選び直しはそのまま（20260921-theme-settings で既にある機能。この work では触らない）。
- `.aidev/backlog/product-roadmap.md` の該当行（「テーマの色の個別の上書き」）を、着地の根拠つきで `[x]` にする。
- 上書きの対象は、本製品が実際に使う CSS 変数（`packages/web/src/theme/uiTokens.ts` の `CSS_VARS`。19 個）。herdr の `[theme.custom]` の
  トークン名（`accent`・`panel_bg`・`surface0` 等。Catppuccin 由来の中間の意味付け）とは 1:1 に対応しない——本製品はテーマごとに
  この 19 個の CSS 変数を直接計算しているため（design で対応表を示す）。
- 上書きは「明るいとき」「暗いとき」の 2 組（herdr の `.light`/`.dark` に相当）。**herdr の「常に（`theme.custom` 本体）」に当たる
  第 3 の組は持たない**（本製品はテーマ自体を明暗の対で選ぶ設計〔20260921-theme-settings〕なので、2 組で герdr と同等の実用性がある。
  design に理由を書く）。
- 値は CSS の色として妥当な文字列（16 進・`rgb()`・色名等。判定の具体的な方法は design で決める——単体テストで拒否側を
  確かめられる手段を選ぶ）。
- 上書きは選んだテーマの計算結果（コントラストを調整した後の値）の**上に、そのまま**当てる（herdr と同じ——上書きした色に自動のコントラスト
  調整はしない。利用者の意図した色をそのまま反映する）。
- 保存はこのブラウザだけ（既存の設定と同じ `wtm.prefs.v1`）。既定との差だけを持つ。
- 色ごとに既定へ戻せる。すべてまとめて既定へ戻せる（確認あり。既存の「キー」節の「すべて既定に戻す」と同じ扱い）。
- `docs/herdr-parity.md`・`docs/verification.md` の更新。

### 対象外

- herdr の 19 トークンをそのまま持ち込むこと（本製品の 19 個の CSS 変数への対応表で置き換える。上の「対象」参照）。
- サイドバーの背景・選択行の背景を**独立した新しい見た目の要素**として追加すること（herdr にはある `sidebar_bg`・`selection_bg`
  相当の見た目の区別が本製品に無いものは、既存の対応する CSS 変数〔`--wtm-menu-bg`・`--wtm-menu-active-bg`〕への上書きで代える。
  新しい見た目の要素の追加は別の後続）。
- 上書きした値の自動のコントラスト補正・警告の計算（herdr にも無い。上書きは利用者の責任）。
- 「設定の再読み込み」（H25b）：herdr の設定ファイルの再読み込みに相当する機能は、本製品には外部の設定ファイルが無いため存在しない
  （変更は既存のどの設定とも同じく押した瞬間に反映・保存される）。H25b の「onboarding」も本 work の対象外（別の後続）。
- 明暗の変化を端末の中のアプリへ知らせる（DSR 996 / mode 2031）・端末の選択の背景の見やすさ（herdr 由来の配色そのものの改善）は、
  この work とは別に backlog へ起票済み（別の後続）。

## 機能要件

- 設定画面の節「テーマ」に、19 個の CSS 変数それぞれについて、「明るいとき」「暗いとき」の上書きを入力できる。
- 入力した値が CSS の色として妥当なら、即座に反映・保存する（確定ボタンは置かない。既存の節と同じ）。
- 妥当でなければ、理由を示し、反映も保存もしない（元の値のまま）。
- 各色に、上書きしているときだけ「既定に戻す」ボタンが出る。
- 「すべての上書きを既定に戻す」ボタン（確認を挟む。取り消せないため）。
- 上書きは、選んだテーマの計算済みの値（コントラスト調整後）の上から当たる。テーマを選び直しても上書きは残る（値ごとの上書きなので、
  別のテーマに替えても同じ CSS 変数の上書きがそのまま当たる。herdr と同じ）。
- 各色の入力の隣に、その色が実際どこで使われるかの短い説明（例：「アクセント（強調の色）」）を出す（受け入れ: AC12）。

## 非機能要件 / 制約

- 保存の形は既存の設定と同じ規約（`wtm.prefs.v1` に既定との差だけを追記。壊れた値は値ごとに落として起動不能にしない）。
- 反映は `ThemeController` の適用経路（`apply` → CSS 変数を `document.documentElement` へ）に乗せる。テーマそのものの計算
  （`uiTokens.ts`・コントラスト調整）には手を入れない。いま画面に当たっているテーマの見た目（`colorScheme`。`light`／`dark`
  のどちらか。既存の `effectiveTheme`＝いま解決しているテーマの名前から決まる）で、「明るいとき」「暗いとき」のどちらの
  上書きが効くかを選ぶ。
- 起動用の控え（`theme-boot.js`・`BOOT_KEY`）にも上書きを含める（読み込み直後に一瞬既定の色が出ないよう）。
- 設定画面は既存のダイアログ（キー入力はここでは prefix や直接のキーに奪われない。既存の他の入力欄と同じ扱い）。

## 相互作用の受け入れ基準

- [ ] AC-I1 開く / 閉じる: 節「テーマ」の中に、折りたたみ（`<details>`）で上書きの一覧を出す。既定では閉じている（19×2＝38 の入力が
  常に見えると節が長くなりすぎるため）。開閉はブラウザ標準（Enter/Space・クリック）。
- [ ] AC-I2 確定 / 取り消し: 確定は入力欄からフォーカスが外れる（`change`）か Enter。無効な値は理由を示して元の値のまま（保存しない）。
  「すべて既定に戻す」は取り消せない操作なので、インライン確認を挟む（キーの節と同じ形）。
- [ ] AC-I3 キーボードだけで完結するか: 節を開く→上書きの折りたたみを開く→入力欄へ Tab→値を入れて Enter/Tab で確定→「既定に戻す」ボタンへ
  Tab→Enter、をマウス無しで通せるか。
- [ ] AC-I4 フォーカスの行き先: 確定してもフォーカスは動かさない（同じ入力欄に留まる。テキスト入力なので、キーの取り込みのように
  フォーカスを移す必要が無い）。「既定に戻す」を押すと、その色の上書きが消えて入力欄が空になり（機能要件のとおりボタン自体も消える）、
  フォーカスは同じ行の入力欄へ移る（消えるボタンに取り残されない）。
- [ ] AC-I5 既存の操作を妨げないか: 入力欄でのキー操作（矢印・Ctrl+A 等のテキスト編集）は、prefix や直接のキーに奪われない
  （非機能要件の「設定画面は既存のダイアログ」と同じ扱い。既存の他の入力欄と同じ）。
