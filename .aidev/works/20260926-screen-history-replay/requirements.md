# 要件: 画面履歴の保存と再生（opt-in。herdr の pane screen history 相当）

## 背景 / 課題

サーバ（`wtm serve`）を止めて起動し直すと、workspace・tab・pane・cwd・レイアウト・フォーカスは
`session.json` から戻るが（`packages/server/src/persist/SessionFile.ts`・`SessionService.restore`）、
各 pane の画面は**空の新しいシェル**になる。止める直前に何を実行し、どんな出力が出ていたか
（ビルドの失敗・テストの結果・直前のコマンド）は、再起動をまたいで失われる。

herdr には同じ場面のための「pane screen history replay」がある（`docs/herdr-parity.md` の H32、
backlog `product-roadmap.md`「セッション永続化の拡張: 画面履歴の保存と再生（opt-in）〔D8〕」）。
一次資料（herdr v0.9.1 の `docs/.../session-state.mdx`「Pane screen history replay」節と
`src/persist/*.rs`・`src/pane/terminal.rs` の `seed_history_ansi`）では:

- 設定 `[experimental] pane_history = true` で有効にする。**既定は無効**——pane の出力には秘密
  （token・プロンプト・コマンドの出力）が含まれうるため。
- 保存先は `session.json` の隣の `session-history.json`（`session.json` とは別ファイル）。
- 再起動後、保存した画面（ANSI）を新しい端末に先に流し込んでから、新しいシェルを動かす
  （古いプロセスは戻らない）。
- 公式連携でエージェントの会話を再開する pane には画面履歴を流さない（会話の再開が履歴を持つ）。
- 無効にすると保存済みの履歴ファイルを消す。壊れた `session.json` の退避コピーには画面履歴を含めない。

## 目的 / ゴール

- `--pane-history` を付けて動かしているサーバを止めて起動し直したとき、各 pane に**止める直前の画面と
  スクロールバック**が見え、そこが「前回のセッションの画面」で今のシェルとは別物だと分かる状態。
- 付けない利用者には何も変わらず、画面の内容がディスクに一切残らない状態（以前に付けて保存した分も残らない）。
- 保存した画面のファイルが、状態ディレクトリの外に書かれず・他人に読めず・際限なく大きくならず、
  中身を書き換えられても新しいシェルへの入力や端末のモード変更に化けない状態。

## ユーザーストーリー

- US1: サーバを更新・再起動する利用者として、再起動の後も直前の出力（エラー・結果）を見返したい。
  なぜなら、再起動のたびに画面が空になると、何をしていたか・どこで失敗したかを思い出すために同じコマンドを
  実行し直さなければならないから。（受け入れ: AC1, AC2, AC3, AC5, AC12）
- US2: 秘密を扱う利用者（既定の利用者）として、明示的に有効にしない限り画面の内容をディスクに残してほしくない。
  また有効にした後で無効に戻したら、保存済みの分も消えてほしい。なぜなら、pane の出力には token や
  パスワードのプロンプトが含まれうるから。（受け入れ: AC4, AC11）
- US3: 運用者として、画面履歴のファイルが状態ディレクトリの中の決まった場所に、所有者だけが読める権限で、
  上限のある大きさで置かれてほしい。また壊れた・書き換えられたファイルでサーバが落ちたり、シェルへ勝手な
  入力が送られたりしないでほしい。なぜなら、履歴は端末の履歴と同じく機微な情報で、ファイルは外から触れうるから。
  （受け入れ: AC6, AC7, AC8, AC13）
- US4: Claude Code 等の会話を公式連携で自動再開している利用者として、再開する pane には古い画面を重ねないでほしい。
  なぜなら、会話の再開が自分の画面を描くので、古い画面が重なると紛らわしいから（herdr と同じ扱い）。（受け入れ: AC9）
- US5: herdr から移ってきた利用者として、この機能の使い方と herdr との違いを docs で知りたい。
  なぜなら、herdr では設定ファイルで有効にするので、同じ設定を探して迷うから。（受け入れ: AC10）

## スコープ

### 対象

- `wtm serve` に画面履歴を有効にする指定を足す（既定は無効）。
- 有効なとき、各 pane の画面とスクロールバック（サーバのミラーが持つ分）を状態ディレクトリの
  `session-history.json` に定期的と停止時に保存する。
- 有効なとき、起動時の復元で、保存した画面を各 pane に先に表示し、その後ろに「前回のセッションの画面」で
  あることを示す区切りを出してから、新しいシェルを動かす。
- 無効で起動したときは、保存済みの `session-history.json` を消す。
- ファイルの権限・大きさの上限・壊れたファイルの扱い・流し込む内容の制限（安全化）。
- 利用者向け docs（`docs/tls-setup.md` の起動オプションの節・`docs/verification.md`）と
  `docs/herdr-parity.md` の H32 行の更新。

### 対象外

- **設定画面（ブラウザ）からの有効・無効の切り替え**（herdr は設定ファイルと Settings > Experiments）。
  このリポジトリには設定ファイルの機構が無く、既存のサーバ全体の指定は CLI フラグ（`--worktree-dir` 等）。
  backlog に兄弟の行として残す。
- **live handoff**（更新時にプロセスを生かしたまま引き継ぐ。backlog の別の行）。
- **代替画面（vim・less 等）の中身の保存**。保存するのは通常の画面とスクロールバック（代替画面の中にいても
  通常の画面の履歴を保存する。F2・AC1）。止める時点で動いていたアプリの画面そのものは戻らない。
- 保存した画面の中の端末のモード（マウス報告・bracketed paste・カーソルキーのモード等）の復元。
  古いプロセスは戻らないので、モードは戻さない。
- 異常終了（`kill -9`・停電）の直前の出力をすべて保存すること。定期保存の間隔ぶんは失われうる。
- 保存した画面の暗号化。
- E2E（packages/e2e）の追加・実行（利用者の方針）。

## 機能要件

- F1: `wtm serve --pane-history` で画面履歴を有効にする。指定しなければ無効。
- F2: 有効なとき、サーバは各 pane の通常の画面とスクロールバック（色・太字等の見た目を含む）を
  状態ディレクトリの `session-history.json` に保存する。代替画面（vim・less 等）を使っている pane でも、通常の画面の側を保存する。
  pane ごとの保存量が上限を超えるときは、古い側を捨てて新しい側を残す。保存は一定の間隔で（出力が無ければ書かない）、
  および正常な停止の時に行う。
- F3: 有効なとき、`session.json` からの復元で、各 pane の新しいシェルが何かを出す前に、その pane の
  保存した画面をスクロールバックと画面に表示し、その後ろに「前回のセッションの画面」であることを示す
  区切りの行を出す。新しいシェルのプロンプトは区切りの後ろに出る。
- F4: 保存した画面が無い・空の pane は、今までどおり空の新しいシェルになる。
- F5: 無効で起動したとき、`session-history.json` があれば消す。`session.json` が無い・壊れていて
  新しく始めるときも、古い画面履歴を新しい pane に取り違えないよう使わない。
- F6: 公式連携で会話を自動再開する pane（保存した会話参照があり、自動再開が有効で、再開のコマンドがある）には
  保存した画面を流さない。
- F7: 保存した画面を流すとき、見た目（文字・色・属性）とカーソルの移動の範囲を超える制御
  （端末への問い合わせ・モードの変更・タイトル等）は取り除く。

## 非機能要件 / 制約

- `session-history.json` は状態ディレクトリ（`--state-dir`／名前付き session の状態ディレクトリ）の直下にだけ置く。
  パスに外からの入力を使わない。POSIX では 0600（既存の `session.json` と同じ書き方）。
- 大きさに上限を置く（pane ごと・ファイル全体）。上限を超える pane は古い側を捨てて保存し（F2）、上限を超えるファイルは読まない。
- 壊れた・形の合わないファイルでは起動を止めない（画面履歴なしで復元する）。退避コピーは作らない
  （herdr と同じく、退避コピーに画面の内容を残さない）。
- 既存の `session.json` の形式は変えない（画面履歴は別ファイル）。以前の版のサーバは `session-history.json` を
  知らないまま動く。
- 保存が失敗しても、`session.json` の保存・サーバの動作は止めない（ログに残す）。
- 対象 OS は Linux / WSL2 / Windows（Windows では権限の代わりに状態ディレクトリの置き場所で守る。既存と同じ）。

## 完了条件 (受け入れ基準)

- [ ] AC1: `--pane-history` を付けて動かしたサーバで、pane に出力（色付きを含む）を出してから正常に停止すると、
  状態ディレクトリに `session-history.json` ができ、その pane の画面とスクロールバックの内容が入っている。
  代替画面を使うアプリの中で停止しても、通常の画面の側の内容が入っている。
- [ ] AC2: AC1 の後に `--pane-history` を付けて起動し直すと、その pane の画面（サーバが pane ごとに持つ端末の写し。ブラウザが接続したときに受け取る画面の元）に、
  保存した内容（文字と色）・その後ろの「前回のセッションの画面」を示す区切りの行・新しいシェルの出力が、この順に並ぶ。
- [ ] AC3: 有効なとき、停止を待たずに一定の間隔でも保存される（出力の無い間は書き直さない）。
- [ ] AC4: `--pane-history` を付けずに動かしたサーバは `session-history.json` を作らず、起動時に既存の
  `session-history.json` を消す。復元した pane は今までどおり空の新しいシェルになる。
- [ ] AC5: `session.json` が無い・壊れているときは、`session-history.json` があっても新しい pane に流さない。
- [ ] AC6: `session-history.json` は状態ディレクトリの直下に作られ、POSIX では権限が 0600。
- [ ] AC7: pane ごとの保存量とファイル全体の大きさに上限があり、上限を超える pane は古い側を捨てて保存し、
  上限を超えるファイル・壊れたファイル・形の合わないファイルは読まずに（起動は続けて）画面履歴なしで復元する。
- [ ] AC8: 保存した内容に端末への問い合わせ・モード変更・OSC 等を含むように書き換えたファイルを流しても、
  新しいシェルへ応答が書き込まれず、端末のモードも変わらない（見た目とカーソルの移動だけが残る）。
- [ ] AC9: 保存した会話参照があり自動再開が有効で再開のコマンドがある pane には、保存した画面を流さない。
  自動再開が無効なら流す。
- [ ] AC10: `docs/tls-setup.md` に `--pane-history` の説明（既定は無効・保存先・秘密の注意・無効にすると消える）、
  `docs/verification.md` に手動確認の手順、`docs/herdr-parity.md` の H32 に対応と herdr との違いが書かれている。
- [ ] AC11: `wtm serve` の使い方の表示に `--pane-history` があり、有効で起動したときは起動の表示で
  画面履歴を保存することが分かる。
- [ ] AC12: 有効で `session.json` も正常なとき、保存した画面が無い pane（保存の後に作った pane・何も出していない pane）は、
  区切りの行も出さずに今までどおり空の新しいシェルになる（F4）。
- [ ] AC13: `session-history.json` の保存が失敗しても（書けない場所等）、`session.json` の保存と停止は続き、失敗はログに残る。
  `session.json` の形式（項目）は変わらない。
