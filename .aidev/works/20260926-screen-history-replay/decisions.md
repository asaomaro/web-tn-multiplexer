# 判断の記録（20260926-screen-history-replay）

## D1: 着手の判断と範囲（autonomous・full）

- **背景**: backlog `product-roadmap.md`「セッション永続化の拡張: 画面履歴の保存と再生（opt-in）〔D8〕」を
  autonomous で処理する。依存 `20260918-web-terminal-multiplexer` は着地済み。herdr の一次資料は
  リポジトリの外の調査用の複製（main の `scratchpad/herdr`。v0.9.1 の docs と `src/`）を主エージェントが直読した。
- **決定**: full で進める（サーバの保存・復元・端末の流し込み・CLI・docs にまたがり、秘密を扱う保存を新しく作るため
  light の「振る舞いを変えない小規模」に当たらない）。有効化は `wtm serve --pane-history`（CLI フラグ）だけにし、
  設定画面からの切り替えは対象外として backlog に残す。
- **理由・代替案**:
  - herdr は設定ファイル `[experimental] pane_history` と TUI の設定画面。このリポジトリには設定ファイルの機構が無く、
    サーバ全体の指定は CLI フラグの慣習（`--worktree-dir` の decisions・`docs/herdr-parity.md` H37）。
  - 代替: 公式連携の自動再開と同じく `integrations.json` 型のファイルに持ち、設定画面で切り替える案。ログインした
    どのブラウザからでも「画面をディスクに残す」を有効にできることになり、秘密を扱う既定無効の機能としては
    サーバを起動する人の明示の指定のほうが安全側。UI（設定画面・protocol のメソッド）まで広がるので分ける。
- **影響**: 範囲外の「設定画面からの切り替え」を deliver で backlog に `[ ]` として足す。

## D2: 保存の時機を session の保存と分ける（design）

- **背景**: herdr は session の保存のたびに画面履歴も書く（research F1）。本製品の `persist.touch()` はフォーカスの変更でも走る。
  直列化は 1 万行で約 100ms（research F5）で、pane が多いとイベントループを秒単位で塞ぐ。
- **決定**: 画面履歴は別の定期保存（30 秒ごと。前回取り出した後に出力の無い pane は前回の結果を使い、何も変わらなければ書かない）と停止時の保存にする。
- **理由・代替案**: (a) session の保存に相乗り——フォーカスの操作のたびに全 pane を直列化するので退けた。(b) 停止時だけ——異常終了で全部を失うので退けた。
  (c) 出力のたびに保存——書き込みが多すぎる。
- **影響**: 異常終了では最大 30 秒ぶんの出力が保存されない（requirements の対象外に書いた範囲）。

## D3: 区切りの行を出す（herdr との違い）

- **背景**: herdr は保存した画面をそのまま流すだけで、境目を示さない（research F1）。requirements F3 は「前回のセッションの画面」と分かることを求める。
- **決定**: 流した内容の後ろに薄い色（SGR 2）の 1 行 `--- 前回のセッションの画面（<時刻> に保存）---` を足す。流した内容自体は薄くしない。
- **理由・代替案**: 内容全体を薄くする案は、保存した SGR（色）を書き換える必要があり、色の情報を失う。区切りの 1 行で境目は分かる。
- **影響**: docs の herdr との違いに書く。

## D4: 流す前の安全化は許可リスト

- **背景**: ミラーは問い合わせに応答し、その応答は新しいシェルへの入力になる（research F4）。`session-history.json` は状態ディレクトリにあり、
  書き換えられうる。
- **決定**: 読み込み時に、印字できる文字・CR・LF・TAB・`CSI [0-9;:]* [ABCDXm]` だけを残し、それ以外の制御の並びは並びごと落とす。
- **理由・代替案**: 拒否リスト（DA・CPR・OSC を落とす）は、xterm が応答する並びを漏れなく挙げる必要があり、将来の版で増えうる。
  直列化の出力が使うのは許可リストの範囲だけ（research F2）なので、正しいファイルでは何も失わない。
- **影響**: 他の端末の出力を手で詰めたファイルは見た目が崩れうる（対象外）。

## D5: 上限の値

- **決定**: pane ごと 2 MiB（ANSI の UTF-8）、ファイル全体 64 MiB。pane ごとの上限を超えたら古い側を行の境目で捨てる。ファイル全体は書くときに
  上限を超える pane から積まない、読むときは超えるファイルを読まない。
- **理由**: `--scrollback` の上限 1 万行・120 桁の色付きで約 1.2MB（research F5）なので、pane ごとの上限は普通は当たらない。全体は pane が
  数十あっても足りる大きさで、読み込みのメモリを抑える。

## D6: 取り違え防止の消去に失敗したときは起動を続ける

- **背景**: design の独立点検（ラウンド 2）: `session.json` が無い・壊れた起動で `session-history.json` を消せないまま異常終了すると、
  次の起動で新しい `p1` に古い画面が流れうる、との指摘。
- **決定**: 警告のログを残して起動は続ける（特別な扱いを足さない）。
- **理由・代替案**: 消す（unlink）にはディレクトリの書き込み権が要り、`session.json` の保存（同じディレクトリでの rename）にも同じ権限が要る。
  消せない状態では `session.json` も書けないので、次の起動も `session.json` が無い経路（流さない）を通る。代替の「世代の印を両方のファイルに持つ」は
  `session.json` の形式を変える（requirements の非機能要件に反する）ので退けた。
- **影響**: なし（点検の上限 2 ラウンドに達したので、以後の確認は review に委ねる）。

## D7: 幅の広い画面の流し直しと、巨大な 1 行の切り詰めは今回は直さない（cross の独立点検の nit 2 件）

- **背景**: cross の点検で 2 件。(1) 直列化は書かれていないマスをまたぐ移動を `CSI n C` で出すので、120 桁を超える幅で保存した行を
  120 桁で作るミラー（`SessionService` の `HEADLESS_COLS`）へ流すと、右端を超える移動が止まって後ろの文字が詰まる（実験で確認）。
  (2) 直列化は折り返した行の間に `\r\n` を出さないので、上限 2MiB を超える巨大な 1 論理行があると、行の境目で切る切り詰めが
  その行を丸ごと落とす。
- **決定**: 今回は直さず、既知の制約として docs と backlog に残す。
- **理由・代替案**: (1) 保存した幅を記録して流す前にミラーを広げ、流し終えてから戻す案は、xterm の write の処理と resize の順序の保証
  （新しいシェルの出力より前に戻す）を別に確かめる必要があり、リスクに見合わない。色・文字は失われず、崩れるのは空白の幅だけ。
  (2) 上限に届くのは `--scrollback` を大きくして幅の広い色の多い出力が 1 行に続く場合だけ。途中で切ると ANSI の並びの途中から始まる。
- **影響**: backlog に `[ ]` を 1 行足す（deliver）。

## D8: review ラウンド 1 の差し戻しで決めたこと（設計の追記）

- **背景**: review ラウンド 1（should 2・nit 1）と、その修正の独立点検（T3・T4 のラウンド 2）。
- **決定**:
  1. `FsPaneHistoryFile.clear()` は本体を先に消し（失敗は投げる）、その後に一時ディレクトリを片付ける（失敗は握りつぶす）。
  2. 片付けるのは `writeFileAtomic` の形（`.tmp-`＋英数字 6 文字のディレクトリで、中身が `write` だけか空）で、作られてから 10 分より古いものだけ
     （起動の途中でも `/api/login` が `auth.json` を書きうるので、書いている最中のものを消さない）。
  3. 保存の係は、取り直した内容が前回と同じなら「変化なし」とみなす（書き直しの比較は pane ごとの内容の版 `version`。design「保存」手順 4 の
     「取り出した時刻」をこれに読み替える）。取り出しの時刻 `at` と `savedAt` は進める（次の保存で取り直さない・停止時に書く時刻が古くならない）。
- **理由・代替案**: 2 の代替「clear を listen の前に移す」は、token の作成・bind の順序（D102・D103）を動かすので退けた。
- **影響**: design.md「保存」手順 2・4 と `clear` の説明はこの記録で上書きする（design は承認済みの版を残す）。
