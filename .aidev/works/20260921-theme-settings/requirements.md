# 要件: テーマを選び、OS の明暗に合わせて切り替える（herdr のテーマ）

## 背景 / 課題

本製品の配色は **Dracula 系の暗い配色 1 種に固定**されている。

- 端末の色（文字・背景・カーソル・16 色）は `packages/protocol/src/theme.ts` の `DEFAULT_THEME` 1 つで、
  web の xterm.js（`packages/web/src/term/theme.ts`）とサーバの Mirror（色の問い合わせへの応答。
  `packages/server/src/terminal/Mirror.ts:63-65`）が共有している。
- 画面の枠（サイドバー・tab バー・ダイアログ等）の色は `App.vue` の `:root` の CSS 変数 7 つと、
  各部品に直に書いた色（状態の記号の 4 色・エラーの赤・警告の橙・背景の暗幕など）で決まっている。

herdr には **18 の組み込みテーマ・色の個別の上書き・ホストの端末の明暗に合わせた自動の切替**がある
（`docs/herdr-parity.md` の **H24**。herdr の `src/config/theme.rs` の `THEME_NAMES`・`auto_switch`・
`light_name`/`dark_name`、設定画面 `prefix+s` のテーマの節）。本製品ではどれもできない。

困ること:

1. **明るい場所では暗い画面が読みにくい**。明るい配色を選ぶ手段が無い。
2. **普段のエディタや端末と配色を揃えられない**。CLI・エディタの配色は端末のテーマを前提に作られている。
3. **OS の明暗の自動の切替（夜だけ暗く）に追従しない**。
4. **ただ見た目の色を変えるだけでは、端末の中のアプリが明暗を誤る**。nvim などは起動時に端末へ背景の色を
   問い合わせ（OSC 11）、明暗に合った配色を選ぶ。本製品ではこの問い合わせに**サーバが固定の Dracula の色**で答える
   （ブラウザ側の応答は握りつぶしている。`packages/web/src/term/QueryFilter.ts`）。画面を明るくしても
   アプリは「暗い背景」と判断し、**明るい背景に明るい文字**を出して読めなくなる。
   herdr はホストの端末の実際の色を pane の中へ伝えている（`src/terminal_theme.rs`・`src/app/theme_sync.rs`）。

## 目的 / ゴール

- **利用者が、このブラウザで好みの配色を選べ、画面の枠と端末の中身が揃ってその配色で見える状態**。
- **OS の明暗の設定に合わせて、明るい配色と暗い配色が自動で入れ替わる状態**（選んだ人だけ）。
- **端末の中のアプリが色を問い合わせたとき、その pane の大きさを決めているブラウザ（ふつうはいま操作している人）の画面の色で
  答えが返り、アプリが明暗を正しく選べる状態**。
- **どの配色でも、画面の枠の文字と状態の記号が読める状態**（配色を変えたせいで読めなくならない）。

## ユーザーストーリー

- US1: 明るい部屋や屋外で使う利用者として、**明るい配色を選びたい**。なぜなら、周りが明るいと暗い画面は
  反射で読みにくく、目も疲れるから。（受け入れ: AC1, AC2, AC3, AC10, AC13, AC-I1, AC-I2, AC-I3, AC-I4, AC-I5）
- US2: 普段のエディタや端末で Catppuccin・Tokyo Night などを使っている利用者として、**同じ配色を選びたい**。
  なぜなら、端末の中の CLI・エディタの配色はそのテーマを前提に作られていて、揃うと読みやすく、
  道具を行き来しても目が慣れ直さずに済むから。（受け入れ: AC1, AC2, AC3, AC-I2）
- US3: OS を時刻で明暗切り替えている利用者として、**本製品も自動で合わせてほしい**。
  なぜなら、切り替わるたびに設定を開いて変えるのは手間で、忘れると夜に真っ白な画面を見ることになるから。
  （受け入れ: AC5, AC6, AC7, AC13, AC-I3）
- US4: 端末の中で nvim などを使う利用者として、**アプリが背景の明暗を正しく判断してほしい**。
  なぜなら、明るい配色で暗い背景用の色が出ると、文字が背景に溶けて読めなくなるから。（受け入れ: AC8）
- US5: すべての利用者として、**どの配色でも画面の枠の文字と状態の記号が背景から浮いて読めてほしい**。
  なぜなら、配色を変えたせいでエージェントの状態が読めなくなると、この製品の中心の機能
  （複数のエージェントを見張る）が使えなくなるから。状態を色以外（記号）でも区別する表示は前の work
  （20260921-herdr-settings-gaps）で入っており、テーマに依らない——ここで守るのはコントラスト。（受け入れ: AC9）
- US6: 今の配色のまま使っている利用者として、**何もしなければ見た目が変わらないでほしい**。
  なぜなら、更新のたびに見慣れた画面が黙って変わると、どこが変わったのかを探す手間が生じるから。（受け入れ: AC4）

AC11・AC12（文書）・AC14（起票）はこの work の完了条件で、特定のストーリーに紐づかない。

## スコープ

### 対象

- **組み込みテーマ 17 種**：herdr の `THEME_NAMES` 18 種から `terminal` を除いたもの（catppuccin・catppuccin-latte・
  tokyo-night・tokyo-night-day・dracula・nord・gruvbox・gruvbox-light・one-dark・one-light・solarized・
  solarized-light・kanagawa・kanagawa-lotus・rose-pine・rose-pine-dawn・vesper）。
  **明るいテーマは 7 種**（catppuccin-latte・tokyo-night-day・gruvbox-light・one-light・solarized-light・kanagawa-lotus・
  rose-pine-dawn）、**暗いテーマは 10 種**（残り）。
  **1 つのテーマが、画面の枠の色と端末の色（文字・背景・カーソル・選択・16 色）の両方を決める**。
  端末の色は**各テーマの上流が配る端末の配色**を使う（出典は research で確定する）。dracula は今の `DEFAULT_THEME` と同じ。
  上流の値のままでは選んだ文字やカーソルが見えないテーマには、選択の文字の色とカーソルの色だけ規則で直し、ブロックカーソルの下の文字は背景色で描く
  （design D2・decisions D5・D10）。
- 設定ダイアログ（`prefix+s`・サイドバーの［メニュー］→「設定」・モバイルの上のバーのボタン）に**テーマの節**を足す。
- **OS の明暗に合わせた自動の切替**（明るいとき・暗いときに使うテーマを選べる）。
- 選んだ内容を**このブラウザに保存**し、次に開いたときに**最初の描画から**その配色で出す（ログイン画面を含む）。
- 選び直したら**再読み込み無しで、開いている全 pane を含めて**すぐ変わる。
- 色の問い合わせ（OSC 10・11・12 と OSC 4 の 0〜15）への答えを、**その pane の tab のサイズを決めているブラウザの配色**に合わせる。
- 画面の枠に直に書いた色（状態の記号・エラー・警告・暗幕など）も、テーマに合わせて変わるようにする。
- `docs/herdr-parity.md` の H24 と `docs/verification.md` の更新。
- 対象外に挙げた 2 件（色の個別の上書き・明暗の変化の通知）の backlog への起票（AC14）。

### 対象外

- **色の個別の上書き**（herdr の `[theme.custom]` と `.light`/`.dark`）：herdr でも設定ファイルでだけ変えられ、
  設定画面には無い。本製品には利用者が書く設定ファイルが無い（設定の再読み込みの H25b と合わせて扱う）。
  backlog に起票する。
- **`terminal` テーマ**（画面の枠の色をホストの端末の 16 色に合わせる）：ブラウザではホストの端末が無く、
  端末の色は本製品が決めるので、当てはまらない。
- **明暗が変わったことを端末の中のアプリへ知らせる**（herdr の DSR 996 への応答と mode 2031 の通知。
  `src/terminal_theme.rs` の `HostAppearance::color_scheme_report`）：今も応答していない（後退ではない）。backlog に起票する。
- **テーマをサーバに保存して端末をまたいで共有すること**：OS の明暗は端末ごとに違うので、選んだ内容はこのブラウザに
  だけ残す（既存の設定の節と同じ）。ただし**色の問い合わせに答えるため、いま表示している配色はサーバへ伝える**
  （保存も共有の表示もしない。AC8）。
- 256 色のうち 16〜255 番（テーマに依らない標準の色）。フォントの種類・大きさ。
- 端末の中のアプリが 24 bit の色で直に描いた部分（テーマに依らない。当然そのまま）。

## 機能要件

- 設定ダイアログのテーマの節で、17 のテーマから 1 つを選べる。選んだ結果がその場で見える。
- 自動の切替を入れると、OS（ブラウザ）の明暗に応じて「明るいとき」「暗いとき」のテーマが使われ、
  OS 側を切り替えると追従する。「明るいとき」「暗いとき」は、それぞれ **17 のテーマのどれからでも**選べる
  （herdr の `light_name`/`dark_name` も任意の名前を取る）。
- 自動の切替が入っている間に 1 つのテーマを選ぶ操作をすると、自動の切替は切れ、そのテーマになる
  （herdr の「設定画面で手で選ぶと `auto_switch` が切れる」と同じ）。自動の切替を切ると、選んでいた 1 つのテーマに戻る。
- ブラウザ標準の部品（選択肢・チェックボックス・スクロールバー等）の明暗も、使われているテーマの明暗に合わせる。
- 明るいとき・暗いときのテーマの既定（**まだ選んでいない間**の値。選んでいなければ、1 つのテーマを変えるとその対に追従し、
  一度選んだらその値を保つ——herdr で `light_name`/`dark_name` を書かなければ `name` の対が使われるのと同じ）は、
  選んでいるテーマの**対**（herdr の `sibling_theme_names`：
  catppuccin ↔ catppuccin-latte・tokyo-night ↔ tokyo-night-day・gruvbox ↔ gruvbox-light・one-dark ↔ one-light・
  solarized ↔ solarized-light・kanagawa ↔ kanagawa-lotus・rose-pine ↔ rose-pine-dawn）。
- **画面の見た目（画面の枠と端末の描画の色）はこのブラウザにだけ効き**、ほかのブラウザ・ほかの機器の見た目は変えない。
- 色の問い合わせには、その pane の画面を操作している人（その tab のサイズを決めているブラウザ）が
  表示している配色で答える。その人がテーマを変えたら、以後の答えも変わる。**このため、同じ pane を見ているほかの
  ブラウザにも、アプリの出力（明暗に合わせて選んだ色）を通して影響する**——pane は 1 つの端末で、答えも 1 つしか返せない。
  「サイズを決めているブラウザ」は既存の tab ごとのサイズ権限（最後に入力・フォーカス・レイアウトの操作をした
  デスクトップ、または「この端末に合わせる」を入れたブラウザ。`20260918-web-terminal-multiplexer` の design「サイズ権限」）。
  **限界**：「この端末に合わせる」を入れていないモバイルはサイズを決めないので、そこで入力していても答えはその配色にならない
  （サイズを決めているブラウザが他にあればその配色、無ければ AC8 の決めごと）。

## 非機能要件 / 制約

- **何も設定していない利用者の見た目は今と同じ**（下のコントラストのために直す箇所を除く。既定は dracula。herdr の既定 catppuccin とは違う——
  既存の利用者の見た目を黙って変えない）。**dracula テーマ＝今の `DEFAULT_THEME` と今の画面の枠の色**
  （選択の色も今の画面の選択の色と同じ）。
  今の色が下のコントラストを満たさない箇所があれば、**コントラストを優先して直し**、直した箇所を decisions に残す。
  AC10（ブラウザ標準の部品を暗く描く）も dracula に当てる（decisions D3）。サイドバーの「未検証」を薄めずに描く規則も、全テーマでそろえるため
  dracula に当てる（decisions D16）。それ以外は変えない。
- 保存された値が壊れている・知らない名前のときも**起動できなくならない**（既定へ落とす）。
- 読み込みの直後に**既定の暗い配色が一瞬出てから切り替わる、ということが無い**（明るいテーマで特に目立つ）。
- 画面の枠の色は **WCAG 2.2 のコントラスト**を満たす：文字は背景に対して 4.5:1 以上（1.4.3）、
  状態の記号・フォーカスの枠・入力欄の枠は隣の色に対して 3:1 以上（1.4.11）。**全テーマで**。
  端末の 16 色は各テーマの上流が配る値を使う（dracula だけは今の `DEFAULT_THEME`。アプリが出す色の組み合わせは本製品が決められない）。
- 設定は既存の設定の節と同じ保存先・同じ寿命（このブラウザ・このプロファイル）で持つ。
- デスクトップとモバイルの両方で効く（確かめる範囲は AC13）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く / 閉じる: テーマの節は既存の設定ダイアログの中にあり、既存の 3 つの入口で開き、既存どおり
      Esc・背景のクリック・閉じるボタンで閉じる。
- [ ] AC-I2 確定 / 取り消し: テーマを選んだ結果が**その場で見え**、気に入らなければ**元のテーマへ戻せる**。
      （design D4 で決めた内容）1 つのテーマ・明るいとき／暗いとき・自動の切替の入切の 4 つとも、**選んだ・押した時点で反映と保存**
      （確定ボタンは無い）。取り消しは**選び直し・押し直し**で、開く前のテーマを選び直せば元に戻る。Esc・背景のクリック・［閉じる］の
      3 つの閉じ方は**どれも選んだ結果を保つ**（既存の設定の節と同じ）。
- [ ] AC-I3 キーボードだけで完結するか: `prefix+s` → テーマの節へ移る → テーマを選ぶ → 自動の切替を入れて
      明るいとき・暗いときを選ぶ → 閉じる、がマウス無しで通せる。
- [ ] AC-I4 フォーカスの行き先: 開いたときと閉じたときは既存の設定ダイアログと同じ（閉じたら開く前にいた場所へ戻る）。
      テーマを選んでも、フォーカスが選んだ部品から外れない（配色の入れ替えで失われない）。
- [ ] AC-I5 既存の操作を妨げないか: テーマの選択肢の上の矢印キー・ホイールを端末やほかのショートカットへ漏らさない。
      テーマを変えても、端末の中身（画面・スクロールの位置・選択の有無）と、シェルに打ちかけの入力行が失われない。
