# 要件: workspace の既定の名前を、開いた場所（リポジトリ）から自動で付ける

## 背景 / 課題

新しい workspace の名前は、**どこで開いても一律に「1」**になる（`packages/server/src/session/SessionService.ts:157` の `label ?? "1"`、
起動時と最後の workspace を閉じた後の作り直しも `:475`・`:482` で `"1"`）。名前は、サイドバーの spaces 欄と agents 欄
（`packages/web/src/components/Sidebar.vue:163`・`:197`）・goto の一覧と絞り込み（`GotoPicker.vue:95`・`:97`）・モバイルの上のバーとピッカー
（`mobile/MobileShell.vue:46`・`mobile/PanePicker.vue:93`・`:110`）・通知の場所（`notify/describe.ts:40`）・ブラウザのタブの題名（`main.ts:243`）の
9 か所に出るが、どれも `Workspace.label` をそのまま読む。

直前の work（`20260921-new-terminal-cwd`）で、pane で別のリポジトリへ移ってから新しい workspace を作ると、そのリポジトリで開くようになった。
ところが名前が「1」のままなので、**別のリポジトリで開いた workspace がサイドバーで見分けられない**（同 work の review.md の価値適合の指摘・
`.aidev/backlog/product-roadmap.md` の項目）。worktree を開く・作る操作だけは、この穴への個別の手当てとしてブランチ名（detached なら
パスの末尾）を名前に渡している（`packages/web/src/actions/ActionDispatcher.ts:222-229`・`:251`・`:258` の注記）。

herdr（`herdrdev/herdr` の commit `da6bcd5969779bfe0396bcf89a8025d4375d611e`）は、名前を付けていない workspace に**自動の名前**を付ける
（`src/workspace.rs` の `display_name`：付けた名前 `custom_name` があればそれ、無ければ自動の名前）。自動の名前は、git の中なら
チェックアウトの根のフォルダ名、git の外ならフォルダ名（ホームなら `~`、フォルダ名が無い根ならパスそのもの）
（`src/workspace/git/discovery.rs` の `automatic_workspace_label`・`fallback_label_from_cwd`）。git の根は `.git` をたどって見つける
（同ファイルの `git_repo_root`）。名前を付けると、以後は自動の名前で上書きしない。herdr の画面では、workspace の名前を空にして確定しても
何も起きない（`src/client/shell/overlay_input.rs:955`）——**自動の名前へ戻す操作は herdr に無い**。また、今の名前を入れて開くダイアログ
（`:372`）で**何も変えずに確定すると、自動の名前がそのまま付けた名前として固定される**（`:955` は空でなければ送り、サーバは無条件に
`set_custom_name` する——`src/app/api/workspaces.rs:115`）。tab の名前変更は、自動の名前のまま変えていなければ送らない（`overlay_input.rs` の
`auto_name && trimmed == original_name`）。herdr の worktree を開く・作る操作は名前を渡さない（`src/client/shell/worktrees.rs:272`・`:327`）ので、worktree の workspace も自動の名前（worktree の根のフォルダ名）になる。

## 目的 / ゴール

- **複数のリポジトリで開いた workspace を、名前で見分けられる状態**（サイドバー・goto・モバイル・通知・ブラウザのタブの題名のどこでも、
  どのブラウザでも）。
- **利用者が付けた名前は、自動の名前で上書きされない状態**（再起動をまたいでも）。
- **付けた名前をやめて、自動の名前に戻せる状態**（herdr に無い、本製品が足す操作）。

## ユーザーストーリー

- US1: 複数のリポジトリを並行して見張る利用者として、**workspace がそれぞれのリポジトリの名前で並んでほしい**。なぜなら、いまはどの
  workspace も「1」で、どれがどのリポジトリか開いて確かめないと分からないから。（受け入れ: AC1, AC2, AC3, AC4, AC8, AC9）
- US2: workspace に名前を付けた利用者として、**付けた名前がそのまま残ってほしい**。なぜなら、自動の名前で書き換わると、付けた意味が無くなるから。
  （受け入れ: AC5, AC7, AC10）
- US3: 名前を付けたが自動の名前に戻したい利用者として、**名前を消せば自動の名前に戻ってほしい**。なぜなら、いまは名前を空にできず、
  一度付けた名前をやめる手段が無いから。（受け入れ: AC6, AC10, AC-I2）

## スコープ

### 対象

- workspace の**既定の名前**の決め方（herdr の自動の名前に相当する規則）。
- 名前を付けた workspace と、付けていない workspace の区別（付けた名前を上書きしない・再起動をまたいで保つ）。
- 付けた名前をやめて自動の名前に戻す操作（デスクトップの名前を変えるダイアログから）。
- 以前の版で保存した状態（`session.json`）からの復元の扱い。
- `docs/herdr-parity.md` の該当行と、利用者向けの文書（`docs/verification.md`）。

### 対象外

- **workspace の中で `cd` したときに名前が追従すること**。herdr は最初の tab の根の pane の「いまの場所」から名前を決め直すが、本製品の
  git の情報（サイドバーの 2 行目）は workspace を作った場所（`Workspace.cwd`）から取っている（`packages/server/src/git/GitInfoPoller.ts:47`
  の `probe(ws.cwd)`）。名前だけを追従させると git の情報と食い違うので、両方をまとめて扱う別の work に回す（backlog）。
- tab の名前（最初の tab は「1」、2 つ目以降は tab の数に 1 を足した数——`SessionModel.ts:229`。この work では扱わない）。
- 同じリポジトリで開いた 2 つの workspace を見分ける手当て。**herdr と同じく同じ名前のまま**にする（見分けたければ名前を付ける）。
  同じリポジトリの workspace をまとめる表示は後続「workspace のグルーピング」（`docs/herdr-parity.md` の H37b）。
- **worktree を開く・作る操作が付ける名前**。今までどおりブランチ名（detached ならパスの末尾）を付けた名前として渡す（herdr は渡さず自動の名前に
  なる。本製品のほうがダイアログで選んだブランチ名がそのまま見え、worktree のフォルダ名より情報が多いので変えない。herdr との違いとして対応表に書く）。
- **モバイルから名前を変えること**（名前を変える入口は `prefix+W` とデスクトップの右クリックメニュー——`ContextMenu.vue:78`——だけで、
  モバイルには以前から無い）。自動の名前に戻す操作もデスクトップだけ。
- 新しい版で保存した `session.json` を古い版で読むこと（ダウングレード）の保証。ただし下の制約のとおり、壊れたファイル扱いにはしない。

## 機能要件

- 名前を付けていない workspace の名前は、**その workspace を開いた場所**（`Workspace.cwd`）から自動で決まる:
  - git のリポジトリの中なら、チェックアウトの根のフォルダ名（worktree ならその worktree の根のフォルダ名）。git のコマンドが無い環境でも同じ。
  - git の外なら、その場所のフォルダ名。そのサーバの利用者のホームディレクトリなら `~`。フォルダ名が無い根（`/`・`C:\`）ならパスそのもの。
- **作った時点で自動の名前が付いている**（作った側のブラウザにも、ほかのブラウザにも、最初から自動の名前で出る。「1」や空の名前を一度も出さない）。
- 新しい workspace を作るすべての経路（［＋ 新規］・`prefix+N`・起動時に作る最初の workspace・最後を閉じた後の作り直し）に効く。
- 自動の名前の workspace は、**復元のときにその場所から名前を決め直す**（保存した後にその場所の git の状態が変わった——親で `git init` した・
  `.git` を消した等——ときに、新しい状態の名前になる）。
- 利用者が名前を付けたら、以後は自動の名前で上書きしない。復元で自動の名前を決め直すときも、付けた名前は変えない。
- 名前を変えるダイアログで**名前を空（空白だけを含む）にして確定すると、自動の名前に戻る**。以後は自動の名前として扱う。
- 自動の名前の workspace で名前を変えるダイアログを開き、**何も変えずに確定しても、付けた名前にはしない**（自動のまま。今のダイアログは今の名前を
  入れた状態で開くので、変えていなければ送らない——新しい tab の名前の先例 `NameDialog.vue` の D75 にそろえる）。
- 名前の変化（自動の名前に戻した・名前を付けた）は、開いているほかのブラウザにも再読み込みなしで反映される。
- 以前の版で保存した `session.json` を読んだとき、以前の既定の名前（`"1"`）の workspace は自動の名前の workspace として扱い、それ以外の名前
  （利用者が付けた名前・worktree を開く・作るときに付けたブランチ名）の workspace は付けた名前の workspace として残す。**利用者が自分で「1」と付けていた
  workspace も自動の名前になる**（以前の保存には区別が無いので見分けられない。受け入れる割り切り）。

## 非機能要件 / 制約

- 3 つの OS（Linux・macOS・Windows）で動く。
- workspace を作る操作の応答を、名前を決めるために目立って遅らせない。名前を決める待ちには上限を置く（値は design で決める）。上限を超えたとき
  （ファイルシステムが応答しない等）はその場所のフォルダ名にし、次に決め直す機会（復元）まではそのまま（このときは AC1・AC2 の根の名前にならない）。
- 既存の操作（名前を変える・worktree を開く・復元）の入口は変えない。
- 新しい版で保存した `session.json` を古い版が読んでも、壊れたファイルとして捨てない（保存の形を、古い版が読める範囲で変える）。

## 相互作用の受け入れ基準（UI を伴う work のみ）

変わるのは既存の「名前を変える」ダイアログ（`NameDialog`。新しい tab・tab・pane の名前変更と共用）の、**workspace の名前を変えるときの**確定の振る舞いと
手掛かりの文だけ。開き方・閉じ方・キーボード・フォーカスは今までどおり。

- [ ] AC-I1 開く / 閉じる: 今までどおり（既存の入口——`prefix+W`（Shift+W）・workspace の右クリックメニューの「名前の変更」——で開き、Esc で閉じる。
      閉じたら名前は変わらない）。
- [ ] AC-I2 確定 / 取り消し: workspace の名前を変えるとき、**空（空白だけを含む）で確定すると自動の名前に戻る**（いまは何も起きない——`ActionDispatcher.ts:606`）。
      **変えずに確定しても付けた名前にしない**。workspace の名前を変えるときだけ、ダイアログに「空にすると自動の名前に戻る」ことが分かる手掛かりがある
      （tab・pane の名前変更の見た目は変えない）。取り消し（Esc）では名前を変えない。
- [ ] AC-I3 キーボードだけで完結するか: 今までどおり（名前を消して Enter で確定できる）。
- [ ] AC-I4 フォーカスの行き先: 今までどおり。
- [ ] AC-I5 既存の操作を妨げないか: 今までどおり（ダイアログ中のキーは端末へ漏れない）。

## 未確定事項 / 確認したいこと

- 自動の名前は、上の機能要件（作成の応答に載せる・復元で決め直す・どのブラウザでも同じ）から**サーバで決める**ことになる。git の根は、git の
  コマンドが無くても見つかる方法（herdr と同じく `.git` をたどる等）で探す。**決める待ちの上限の値**と、`.git` がファイルの場合（worktree・
  submodule）の扱いは research / design。
- **「付けた名前かどうか」をどう持つか**（protocol の `Workspace` と `session.json` に項目を足すか）。web の表示箇所（背景の 9 か所）が
  `Workspace.label` をそのまま読んでいるので、`label` を表示用の名前のまま保つほうが影響が小さい。→ design。
