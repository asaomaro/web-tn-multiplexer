# 決定記録

## D1: 作成では名前を決めてから予約と起動へ進む（design の点検 1 ラウンド目の代案を 2 ラウンド目で取り消した）

- 背景: design の点検 1 ラウンド目が、`createWorkspace` の予約の前に await を足すと `placeFor` の注記の不変条件（起動までを同期で進める）と食い違うと
  指摘し、「名前を決める処理を起動と並べ、commit の直前に await する」代案を示した。いったんそれを design D4b にした。
- 決定: 2 ラウンド目の点検が、その形では起動の成功（`wireExit` を付けた後）から commit までの間に await が入り、その間にシェルが終わると
  `closePaneAfterExit` が pane をモデルに見つけられず（`SessionService.ts:436`）、commit の後に死んだ pane が running のまま残ると指摘した。
  そこで**名前を決めてから予約と起動へ進む**形に戻した（design D4b）。名前を渡したとき（worktree）は await しない。
- 理由 / 代替案: 起動を同期で進める不変条件が前提にしているのは分割の孤児のテストで、workspace の作成を通る既存のテストは結果を await している。
  待ちが増えるのは名前を決める時間（ふつう数 ms、上限 200ms）だけ。退けた案：上限 < 猶予を構成で保証する——テストは猶予を 5ms に差し替えるので
  成り立たず、本番でも値の組み合わせに暗黙に依存する。
- 影響: coding（T4）で、既存の起動の順序のテストが落ちないことを確かめる。

## D2: 自動の名前の workspace で変えずに確定しても、付けた名前にしない（herdr の workspace と違う）

- 背景: herdr の画面は、workspace の名前を変えずに確定すると自動の名前をそのまま付けた名前として固定する（`overlay_input.rs:955`・
  `app/api/workspaces.rs:115`）。tab は変えていなければ送らない。
- 決定: 本製品は tab の規則（と新しい tab の D75）にそろえ、変えずに確定したら送らない（requirements・design D7）。herdr との違いとして対応表に書く。
- 理由: 名前のダイアログは今の名前を全選択で開くので、Enter を押しただけで以後自動の名前が追従しなくなるのは気づきにくい。

## D3: T10（テストの実行と記録）は test 工程で消化し、E2E の一式は deliver の直前に回す

- 決定: T10 は coding の承認時に未チェックのまま残し、test 工程で単体一式と影響を受ける E2E の spec を走らせて記録する。E2E の一式は deliver の直前に 1 回
  （利用者の指示「少しの修正ですべて回すのは時間とみあいません」）。
- 理由: `aidev-30-tasks` 手順6。前の work（`20260921-new-terminal-cwd` の decisions D6）と同じ扱い。
