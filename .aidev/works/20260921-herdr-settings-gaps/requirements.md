# 要件: このブラウザの設定を増やす（サイドバーの幅・状態の記号・scrollback）

## 背景 / 課題

前 work（`20260920-agent-notifications`）の調査 F95 で、**herdr の設定（`~/.config/herdr/config.toml` と
`prefix+s` の設定画面）で変えられる項目を全件（132 項目 ＝ 非キー割り当て 69 ＋ キー割り当て 63）**
洗い出し、本製品と突き合わせた。**非キー割り当ての 69 項目**の内訳は
実装済み 3 ／ **機能はあるが設定にできない 22** ／ 未実装 31 ／ 本製品では不要 13
（`.aidev/works/20260920-agent-notifications/research.md` の F95）。

そこから、**利用者がいま実際に困るもの**が backlog に 3 件残っている。

1. **サイドバーの幅と折りたたみが保存されない**（`.aidev/backlog/product-roadmap.md:62`。上の 22 件の 1 つ）。
   ドラッグで変えられて `prefix+b` で畳めるのに、状態はメモリにしか無い。
   **再読み込みのたびに 240px・展開に戻る**。herdr は preferences に保存している。
2. **エージェントの状態が色の点でしか区別できない**（同 `:64`。未実装の側）。
   **色覚特性のある利用者には状態が読めない**。herdr の `ui.status_indicators = symbols` 相当が無い。
3. **scrollback をブラウザ側から決められない**（同 `:65`）。**サーバ起動時の `--scrollback` で
   全員分が決まり**（herdr の `advanced.scrollback_limit_bytes` に対応する実装済みの 3 件の 1 つ）、
   **利用している端末ごとには選べない**。モバイルはコード内で 1000 行に固定されている。
   「この端末では長く持ちたい」「携帯では軽くしたい」に応えられない。

加えて、前 work で `prefix+s` に**通知だけの設定ダイアログ**を置いた。設定が増える以上、
**そこが「設定」の入口として成り立っているか**もこの work で決める（herdr は設定を 1 画面に集約している。
対応表の **H25**「設定画面・設定の再読み込み・onboarding」）。

**モバイルにはサイドバーも prefix キーも無い**（`packages/web/src/mobile/MobileShell.vue`）。
上のバーの 🔔 が設定への唯一の入口で、いまは通知の設定しか開けない。

## 目的 / ゴール

- **ブラウザを閉じても、その端末に合わせた見え方が戻ってくる状態**
  （幅を広げた人は広いまま、畳んだ人は畳んだまま開く）。
- **色に頼らずエージェントの状態が読める状態**（記号でも区別が付く）。
- **サーバが許す範囲の中で、端末ごとに scrollback の量を決められる状態**
  （母艦は長く、携帯は軽く。上限はサーバの `--scrollback` が決める）。
- **設定が増えても、利用者が 1 か所で見つけられる状態。モバイルからも同じように辿れる**。

## ユーザーストーリー

- US1: 利用者として、**サイドバーの幅と折りたたみを覚えていてほしい**。
  なぜなら、毎回同じ調整をやり直すのは、道具が自分の使い方を覚えていないということだから。
  （受け入れ: AC1, AC2, AC3）
- US2: **色の見分けが付きにくい利用者**として、エージェントが入力待ちなのか作業中なのかを
  **色以外でも**知りたい。なぜなら、いま点の色だけが手掛かりで、**状態が読めないと
  この製品の中心の機能（複数のエージェントを見張る）がまるごと使えない**から。
  （受け入れ: AC3, AC4, AC5, AC6, AC7, AC8）
- US3: 携帯から見る利用者として、**scrollback を自分で決めたい**。
  なぜなら、母艦では長い履歴を遡りたいが、携帯では速さと電池のほうが大事だから。
  （受け入れ: AC3, AC9, AC10, AC11）
- US4: 利用者として、**設定を 1 か所で探したい。携帯でも同じように**。
  なぜなら、項目が増えるほど「どこで変えるのか」を覚えていられないから。
  （受け入れ: AC12, AC13, AC14, AC-I1, AC-I2, AC-I3, AC-I4, AC-I5）

## スコープ

### 対象

- サイドバーの**幅**と**折りたたみ**の保存（このブラウザだけ）。
- エージェントの状態の**記号表示**（色に加えて字形で区別する。切り替えられる）。
- **scrollback のクライアント設定**（このブラウザだけ。新しく開く pane に効く）。
- `prefix+s` の設定ダイアログを、**節に分かれた「設定」**へ広げる（通知はその 1 節になる）。
- **設定への入口を 3 つそろえる**：`prefix+s` ／ サイドバーの［メニュー］の項目
  （いまの「通知の設定」を「設定」に改める）／ **モバイルの上のバーのボタン**
  （いまの 🔔 は通知の設定だけを開くので、設定全体を開くように改める）。
- `docs/herdr-parity.md` の該当行（H06・H19・H25）の更新と、状態の記号に対応する行の追加。

### 対象外

- **キー割り当ての変更**（F95 の価値②。対応表 H26）。別 work。規模が違う
  （割り当ての表・衝突の解決・保存・表示）。
- **テーマと明暗の追従**（同③。H24）。別 work。CSS 変数の設計から要る。
- **新しい workspace の cwd**（同⑤。backlog `:63`）。protocol とサーバに届くので別 work。
- サーバ側の既定値（`--scrollback`）の変更。
- 設定をサーバへ保存して**端末をまたいで共有**すること（この work は「このブラウザだけ」）。
- サイドバーの行の内容・色のカスタマイズ（H21）。
- 既に開いている pane の scrollback を遡って変えること。

## 機能要件

- サイドバーの幅・折りたたみは、変えた時点でこのブラウザに残し、次に開いたときに戻す。
- 状態の記号表示は**既定で入**にする（色だけに頼る状態を既定にしない）。設定で切れる。
- 記号は **blocked / working / done / idle / unknown の 5 つが互いに見分けられる**こと。
  **エージェントが居ない行には記号を出さない**（いまと同じ見え方）。
- scrollback は設定で行数を選べ、変えたら**その後に開く pane** から効く。
- 設定ダイアログは節に分かれ、**通知・表示・端末**が 1 つの画面から辿れる。
- **入口を 3 つそろえる**：`prefix+s` ／ サイドバーの［メニュー］の項目（いまの「通知の設定」を
  「設定」に改める）／ モバイルの上のバーのボタン。**どれも同じ設定ダイアログを開く**。
- 設定は**このブラウザにだけ効き**、他のブラウザ・他の端末には影響しない。

## 非機能要件 / 制約

- **web のみで完結する**（protocol・server は変更しない）。
- **既存の入口が使えなくならない**こと（ドラッグでの幅変更・`prefix+b`・`prefix+s`・
  サイドバーの［メニュー］・モバイルの上のバー）。**開く先が設定全体に広がるのは意図した変更**で、
  「壊さない」はこの 3 つの入口が消えない・別のキーに移らないことを指す。
- 保存された値が壊れている／範囲外でも、**起動できなくならない**こと（既定へ落とす）。
- 幅の保存が、ドラッグの手触りを損なわないこと（引っ掛かりを感じさせない）。

## 未確定事項 / 確認したいこと

- 記号の**字形**（どの文字を 5 状態に割り当てるか）。**フォントの有無で崩れないこと**と
  **5 つの見分けが付くこと**を両立させる必要があり、絵文字は環境差が大きい。
  → research で herdr の `status_indicators` の実装と、既存の `sidebar-state-icon` を見て決める。
- scrollback の**選択肢**（自由入力か、段階か）と既定値。サーバの `--scrollback` との関係
  （クライアントが大きい値を求めたときどうなるか）。
- 設定ダイアログを**今の 1 枚に節を足す**のか、**節を切り替える形**にするのか。
  項目数が 3 節で 6〜8 個なら 1 枚に収まる見込み。
- 幅の保存の**書き込み頻度**（ドラッグ中に毎フレーム書かない形にする必要があるか）。
- モバイルの上のバーのボタンの**見た目**（🔔 のままにするか、設定を表す字形へ変えるか）。
