# 要件: タブバーと pane の枠の外観設定（herdr の `tab_bar_*`・`pane_*` 相当）

## 背景 / 課題

herdr の設定は `ui.*` に外観の細かい調整が多数あるが、本製品の設定画面（節「表示」）がまだ持っていないものが残っている。
20260921-herdr-settings-gaps でサイドバーの幅の保存・状態表示の記号化は埋めたが、tab バーの配置・自動非表示・右端の
状態表示と、pane の枠・隙間・エージェント名表示は未対応（`docs/herdr-parity.md` H22・H23、`.aidev/backlog/product-roadmap.md`
の「外観と設定の残り」の一部）。herdr に慣れた利用者が、本製品でも同じ見た目に寄せられない状態が続いている。

## 目的 / ゴール

herdr の `ui.tab_bar_position` / `ui.hide_tab_bar_when_single_tab` / `ui.tab_bar_right` / `ui.tab_bar_right_separator` と
`ui.pane_borders` / `ui.pane_outer_borders` / `ui.pane_gaps` / `ui.show_agent_labels_on_pane_borders` に相当する項目を、
設定画面の節「表示」から選べる状態。既定値は現状の挙動と同じにする（何も変えなければ画面は変わらない）。

## ユーザーストーリー

- US1: 複数 pane を並べて作業する利用者として、pane の枠の描画（自動・常に・なし）と外周の枠・pane 間の隙間の有無を
  選びたい。なぜなら、分割数が多い画面では枠の分だけ端末の表示領域が削られるのを避けたいことがあり、逆に見やすさの
  ために枠を強調したいこともあるから。（受け入れ: AC5, AC6, AC7）
- US2: 複数のエージェントを並行稼働させる利用者として、pane の枠にエージェント名を表示したい。なぜなら、手動で
  pane 名を付けなくても、どの pane でどのエージェントが動いているかを一目で見分けたいから。（受け入れ: AC8）
- US3: tab を 1 つしか使わない workspace が多い利用者として、tab が 1 つのときは tab バーを自動的に隠したい。
  なぜなら、常時表示だと画面領域を無駄に使うから。（受け入れ: AC2）
- US4: herdr から移ってきた利用者として、tab バーを画面下に置き、右端に時刻や接続先ホスト名・zoom 状態を表示したい。
  なぜなら、herdr で使い慣れた配置・情報表示を保ちたいから。（受け入れ: AC1, AC3, AC4）

## スコープ

### 対象

設定画面の節「表示」に次を追加する（既存の節を使う。新しい節は起こさない）。

- tab バーの位置（上 / 下）
- tab が 1 つの workspace のとき tab バーを自動的に隠す（入切）
- tab バー右端の表示エントリ（zoom 状態・接続先ホスト名・日時・固定文字列。複数個・順序込みで組み立てられる）と、
  エントリどうしの区切り文字列
- pane の枠の描画（自動 / 常に / なし）
- pane の外周の枠の有無（入切）
- pane 間の隙間の有無（入切）
- pane の枠へのエージェント名表示（入切。手動の pane 名が付いているときはそちらを優先し、無いときだけエージェント名を出す）

### 対象外

- **pane の scrollbar**（herdr `ui.pane_scrollbars` 相当）：本製品にスクロールバーの UI 自体が無く、ドラッグ可能な
  ウィジェットの新規実装が要る（トグル 1 つでは済まない）。別 work とする。
- **tab バー右端の Command エントリ**（herdr `tab_bar_right` の `command` 種別。任意コマンドを定期実行して結果を表示）：
  サーバで任意のコマンドを走らせる仕組みと権限の設計が要る。20260921-keybinding-customization が対象外にした
  「独自コマンドのキー」（H12）と同じ理由で見送る。
- **サイドバー行のカスタマイズ**（herdr `ui.sidebar` 相当。H21）：行の構成トークン・エージェントごとの上書き・
  条件付き色のルールエンジン（`equals`/`contains`/`starts_with`/`gt`/`lt`）を持つ、この work 単体よりずっと大きい
  独立した機能。別 work とする。
- **設定画面の再読み込み・onboarding**（H25b）：別の UX 上の意思決定が要る。別 work とする。
- 設定ファイルからの読み込み（herdr は `config.toml`）：本製品には利用者が書く設定ファイルが無い。保存はブラウザ
  ごとの既定との差だけ（20260921-theme-settings・20260921-keybinding-customization・20260922-theme-custom-overrides と
  同じ流儀）。**これは製品全体の恒常的な制約で、backlog の個別項目ではない**——AC12 で割って残す対象には数えない
  （残り 4 項目〔scrollbar・Command エントリ・サイドバー行・再読み込み〕だけが backlog の消し込み対象）。

## 機能要件

- 上記「対象」の各項目を設定画面から選べ、選ぶと即座に画面へ反映される（確定ボタンは無い。既存の設定パターンに従う）。
- 保存はブラウザ（プロファイル）ごとに、既定との差だけを持つ（`wtm.prefs.v1`）。壊れた値は項目ごとに落として既定に戻す。
- 別のウィンドウでの変更に `storage` イベントで追従する（既存の設定項目と同じ）。

## 非機能要件 / 制約

- サーバ・protocol の変更は必要な範囲に留める（tab バー右端のホスト名は既存の `session.host.hostname`
  （`main.ts:275`。ブラウザのタブタイトルの書式に既に使っている値。`docs/herdr-parity.md` H14 相当）を
  再利用できる見込みで、新しい通信は増やさない想定。設計で裏取りする）。
- 既定値は現状の挙動と同じにする（回帰させない）。
- pane の呼び名は、既存の唯一の解決規則 `paneNameOf`（`packages/web/src/store/paneName.ts`。手動の `label` →
  エージェントの `label` → 端末の `title` → 既定値の順）を再利用する。新しい解決規則は作らない。

## 未確定事項 / 確認したいこと

- `pane_gaps` の実装方法：`PaneFrame.vue` は現状、pane ごとに 4px の padding を持ち枠を描く構造で、外寸を変えると
  PTY の cols/rows が変わってしまう制約がある（`PaneFrame.vue` のコメント）。隙間の有無を「視覚的な線の有無」で
  表すか「実際の余白」で表すかは design で決める。
- tab バー右端の各エントリの正確な文言・表示形式（日時の書式選択の粒度、固定文字列の入力上限等）は design で決める。
- `pane_borders` の「自動」判定（何を「分割」とみなすか。1 pane の workspace で tab が複数あるときの扱い等）は
  design で決める。
- tab バー右端のホスト名表示が、既存の `session.host.hostname`（サーバ・protocol の変更無し）で本当に賄えるかは
  design で裏取りする（「非機能要件 / 制約」に書いた見込みの確認）。
