# e2e-observe-browser

<!-- 条項の本文。PJ ドキュメントへ移送(promote)するまではここが唯一の在処。 -->

## 規約

**E2E の「できている」の判定は、利用者が見る場所で行う。**

- 判定に使ってよい観測：ブラウザの描画（DOM・スクリーンショット・要素の大きさ）、**ブラウザが受け取った／送った
  フレーム**（CDP の `Network.webSocketFrameReceived` / `webSocketFrameSent`、または中継での記録）、ブラウザが
  サーバへ送った要求。
- テスト自身の WebSocket クライアントは、**前提を作るため**（pane を用意する・入力を流す）と、**サーバ側の状態**の
  確認（PTY の大きさ・セッションの構成）にだけ使う。「利用者に見えているか」をこれで代用しない。
- **テスト自身のクライアントにイベントが届いたことを、ブラウザ側の反映の合図にしない。** 次の操作がブラウザの
  状態（並び順・焦点・保持中の入力）に依るなら、ブラウザ側で観測できる印を待ってから操作する。
- 画面の中身を直接読めない場合（WebGL で描くため DOM から文字を取れない等）は、**何を代わりに観測したか**を
  spec のコメントに書く。固定時間の待ち（`waitForTimeout`）だけを根拠にしない。

## 背景

  全件 pass していた。発見はスクリーンショットの目視。
- **05 の T13**：入れ替えの完了をテスト自身のクライアントの `layout.updated` で判定し、ブラウザがまだ古い並び順の

  間欠的に失敗。2 ラウンド（04 の test・親の統合 test）を「負荷による失敗」と誤って判断させた。
