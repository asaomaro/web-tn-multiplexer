# regression-negative-control

<!-- 条項の本文。PJ ドキュメントへ移送(promote)するまではここが唯一の在処。 -->

## 規約

**回帰テストは「修正前のコードで落ちる」ことを確かめてから採用する。**

- 不具合を直したら、**直した箇所だけを元に戻して**そのテストを走らせ、落ちることを確かめる。確かめたら元に戻し、
  ファイルが一致することを確認する（`diff` / `cmp`）。ビルドした成果物を使うテスト（E2E・起動確認）は、
  **戻した状態でビルドし直してから**走らせる。
- 落ちたときの**生の出力**を `test-result.md`（または対応する記録）に貼る。要約に置き換えない。
- 落ちなければ、そのテストは**その不具合を捕まえていない**。テストを書き直すか、捕まえられない理由を記録して
  別の確かめ方に替える。
- 実装を別のコンテキスト（サブエージェント等）に任せた場合も、**この確認の出力を報告に含めさせる**。

## 背景

`.aidev/works/20260918-web-terminal-multiplexer/retro.md`「うまくいった点」の 2 つ目。毎回この確認を行った結果、
**無効な回帰テストを 3 回検知した**。

- **D98**：「受信を止めて再開すると新しい SNAPSHOT が届く」テストは、修正前のコードでも通ってしまった
  （出力を出し続ける pane はミラーが追いつくたびにも再試行されるため）。不具合の核心（`onDrain` が実物の `ws` で
  呼ばれるか）を直接確かめるテストに差し替えた。
- **T24**：分割で zoom を解除するテストが、「zoom 中の pane 自身を分割したときだけ解除する」実装でも通った。
  別の pane を分割するケースを足して、初めて退行を捕まえられるようになった。
- **T31**：入れ替えの前提を確かめていなかったため、pane の登録が残る不具合を捕まえられていなかった。

`.aidev/config.yml` に `docsRoots` が未設定のため、**既存の PJ ドキュメントとの重複は機械的に確認していない**。
